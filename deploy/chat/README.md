# Serenity adoption chat

The static site calls a dedicated AWS Lambda function URL. The composer design is adapted from sirelog/sire-chat; the browser link renderer and request-state handling also build on the ndungu.dev adaptation. No frontend framework or browser credential is required.

`handler.py` retrieves relevant sections from the committed public documentation corpus and asks OpenRouter for a cited answer. Invalid citation URLs or an unavailable model yield an explicitly labeled documentation excerpt. Unknown topics get an honest no-result response. The assistant has no access to a personal brain.

## Infrastructure

`stack.json` is generated by `python3 deploy/chat/package.py` and reviewed as CloudFormation. It contains the exact handler and compressed public corpus; it contains no secret values. The function role can update only its rate-limit table and read only its own model secret. The deployment copies the configured OPENROUTER_API_KEY environment credential into a dedicated Secrets Manager secret through a NoEcho CloudFormation parameter. The existing ndungu.dev secret was not modified; its metadata exists without an AWSCURRENT value.

Rate limits: 20 requests per hashed visitor IP per hour and 200 requests across the service per day, enforced atomically before model calls. Stored keys use a deployment-specific secret salt, contain no raw IP or conversation, and expire after approximately 25 hours (DynamoDB TTL deletion is asynchronous). The function does not persist transcripts or log prompts. Cloud-provider operational records still apply. Account concurrency is 10; no reservation is made because this account requires all 10 slots to remain unreserved.

The Lambda URL allows the production website origin and the fixed loopback development origin. Origin checks are not authentication; rate limits protect model spend independently. Public questions only.

## Verify and package

```sh
python3 scripts/site/check.py
python3 deploy/chat/package.py
python3 -m unittest discover -s deploy/chat -p 'test_*.py' -v
aws cloudformation validate-template --template-body file://deploy/chat/stack.json --region us-west-2
```

Deployment: `python3 deploy/chat/deploy.py --execute`. This creates a CloudFormation CREATE or UPDATE change set, reports its resource changes, then executes it. Omit --execute to review only. The rate salt is preserved on update. Set OPENROUTER_API_KEY in the process environment to supply model credentials; never place it in command arguments. Never recreate or delete a working stack to update content.

After CloudFormation completes, put its `ChatURL` output into `site/assets/chat-config.js`, commit it, and deploy the Pages workflow. This is a public endpoint, not a credential. Test real POST requests, CORS, citations, model failure fallback, and the installation flow after deployment.

References: [Lambda URL permissions](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html), [GitHub Pages custom domains](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

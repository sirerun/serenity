## T23.6: Client credentials: issue, one-time display, rotate, revoke

### Objective

A reviewer sees that a raw MCP bearer credential is shown exactly once at
issuance, only its SHA-256 verifier is ever persisted, rotation swaps the
raw secret while invalidating the old one immediately, and revocation
locks out every generation a brain has ever issued.

### Scope

Create `internal/hosted/credential/` only: `credential.go` (`Issuer` type,
`Issue`, `Verify`, `Rotate`, `Revoke`), `credential_test.go`. Depends on
`internal/hosted/store` (T23.4) for `client_credentials`. Out of scope: no
HTTP, no gateway wiring (T23.7 consumes `Verify`, does not reimplement
it); does not touch `brains` or `accounts` rows beyond reading the ids
needed to bind a credential.

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/credential`. Raw
credential shape: `sk_live_<prefix>_<secret>` where `prefix` is 8
lowercase-hex characters (`crypto/rand`, 4 random bytes,
`encoding/hex.EncodeToString`) and `secret` is 43 URL-safe base64
characters with no padding (`crypto/rand`, 32 random bytes,
`base64.RawURLEncoding.EncodeToString`), matching the epic's exact
`sk_live_<8-char prefix>_<43-char secret>` shape. `verifier` stored in
`client_credentials.verifier` is `hex(sha256(secret))` -- the prefix
itself is not secret (it is the lookup key, `CredentialByPrefix`) and is
never hashed.

`Issuer{Store *hoststore.Store}`:

- `Issue(ctx, brainID, accountID string, scopes []string) (raw string, err error)`
  generates prefix+secret, inserts one `client_credentials` row with
  `generation = 1`, `revoked_at = NULL`, returns the raw string once. The
  caller (T23.10's dashboard) is responsible for never persisting `raw`
  anywhere; this package never logs it.
- `Verify(ctx, raw string) (Binding, error)` parses `sk_live_<prefix>_<secret>`
  (reject any other shape as `ErrInvalidFormat`), looks up the row by
  `prefix` via `Store.CredentialByPrefix`, and compares
  `crypto/subtle.ConstantTimeCompare([]byte(hex(sha256(secret))), []byte(row.Verifier))`
  -- the same constant-time posture `internal/server/server.go`'s
  `authenticate` already uses for the daemon token, applied here per
  credential instead of per process. A row with `revoked_at` set returns
  `ErrRevoked`; a mismatched hash returns `ErrInvalidCredential` (do not
  distinguish "wrong secret" from "revoked" to a raw byte-compare failure
  path -- only an explicit `revoked_at` produces `ErrRevoked`). Returns
  `Binding{AccountID, BrainID, Generation, Scopes}` on success.
- `Rotate(ctx, brainID string) (raw string, err error)` marks the brain's
  current active (non-revoked) credential row `revoked_at = now`, then
  inserts a new row with `generation = previous.generation + 1`, a fresh
  prefix and secret, same `brain_id`/`account_id`/`scopes`. `Verify(old raw)`
  after this finds the now-revoked row and returns `ErrRevoked`;
  `Verify(new raw)` finds the new row at `generation+1`.
- `Revoke(ctx, brainID string) error` sets `revoked_at = now` on every row
  for that `brain_id`, current and past generations alike, so `Verify`
  fails for all of them.

### Acceptance criteria

- `Issue` returns a raw `sk_live_<8-char prefix>_<43-char secret>` exactly
  once and persists only a SHA-256 verifier.
- `Verify(raw)` returns the binding for a freshly issued credential.
- After `Rotate`, `Verify(old)` returns `ErrRevoked` and `Verify(new)`
  returns the same brain id with `generation+1`.
- `Revoke` makes `Verify` fail for every generation the brain has ever had.
- The raw secret is never written to any log, error message, or returned
  struct field other than `Issue`'s and `Rotate`'s own return value; a
  test asserts `err.Error()` and `Binding`'s fields never contain the raw
  string.
- Genuine red: replace the `crypto/subtle.ConstantTimeCompare` call with a
  plain `==` string comparison, then show (via a benchmark or a documented
  manual timing argument, since a race-free timing test is hard to make
  deterministic in CI) that the comparison short-circuits on the first
  mismatched byte -- or, more directly, temporarily skip the `revoked_at`
  check in `Verify` and show `Verify(old)` after `Rotate` wrongly succeeds
  instead of returning `ErrRevoked`. Restore the check and show the
  correct `ErrRevoked` result. Report both outputs.

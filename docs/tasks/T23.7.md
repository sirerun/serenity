## T23.7: Hosted MCP gateway

### Objective

A reviewer sends real HTTP requests against `internal/hosted/gateway` and
sees: `tools/list` reports exactly `recall`, `remember`, `forget`,
`read_memory_fact` (never `entity` or `synthesize`); a request carrying
one account's session id but another account's credential is rejected
with 401 and the session is not reused; after `Rotate`, the next request
on an already-established session using the old token is 401; scope is
enforced (`memory:write` required for `remember`).

### Scope

Create `internal/hosted/gateway/` only: `gateway.go` (the credential
middleware and per-brain handler cache), `gateway_test.go`. The one
permitted change outside `internal/hosted`: add a `ToolsNamed(names ...string) []mcp.Tool`
method to `internal/server/memory/memory.go`, next to the existing
`Tools()` method (`internal/server/memory/memory.go:307-319`) -- filter
the same five-tool slice `Tools()` builds down to the named subset,
preserving each tool's own `Failure` assignment. This is the only
permitted change under `internal/server/memory`; nothing else in
`internal/server`, `internal/server/mcp`, `internal/store`,
`internal/writer`, or `internal/index` changes. `read_memory_fact` exists
only once PR 224 (T23.1) has merged; if this task starts before T23.1
lands, `ToolsNamed` still works with whatever tools `Tools()` currently
returns, and the `tools/list` acceptance check for `read_memory_fact`
blocks on T23.1 having merged first (it is a listed dependency).

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/gateway`. Do not
reuse `internal/server.Server`: that type wraps every route, including
`/healthz`, in a single global bearer-token compare
(`internal/server/server.go:112-126`), which is exactly the single-user
model ADR 014 says hosted mode does not use. This gateway builds its own
`http.Handler` with its own middleware.

`Gateway{Pool *pool.Pool, Credentials *credential.Issuer, Version string}`
implements `http.Handler`. Per request:

1. Parse the bearer token (`Authorization: Bearer sk_live_...`), same
   header shape Rakazo's client sends. Missing or malformed: 401.
2. `Credentials.Verify(ctx, raw)` (T23.6) resolves `(accountID, brainID,
   generation, scopes)`, or 401 on any `Verify` error.
3. Look up (or open, via `pool.Pool.Open(brainID)`, T23.8) the one
   `*mcp.Server` + `*mcp.HTTPHandler` pair for that brain, built once per
   open brain from `memory.New(deps).ToolsNamed("recall", "remember",
   "forget", "read_memory_fact")` -- an immutable registry, matching
   `mcp.New`'s own immutability (`internal/server/mcp/tools.go:58-102`).
4. Session-generation binding: on a bootstrap POST (no `Mcp-Session-Id`
   header, per `internal/server/mcp/http.go:168-170`'s own branch), after
   the per-brain `HTTPHandler` assigns a new session id and returns it in
   the response's `Mcp-Session-Id` header, the gateway records
   `sessionID -> generation` in its own map (the per-brain `HTTPHandler`
   has no such field; this is new state the gateway keeps alongside it).
   On every subsequent request naming an existing `Mcp-Session-Id`, before
   forwarding to the per-brain handler, compare the credential's current
   `generation` (from step 2) against the recorded one for that session
   id; a mismatch is 401 and the gateway drops its own record for that
   session (it does not call the per-brain handler's DELETE path, since
   the credential presented is not the one that opened the session).
5. Cross-account session reuse: the gateway's session map is keyed by
   `(brainID, sessionID)`, never bare `sessionID` -- an account presenting
   a different account's session id against its own credential resolves
   to a different `brainID` in step 2/3 than the one the session was
   opened under, so the lookup in step 4 misses and the request is
   rejected with 401 rather than silently reusing the other account's
   session.
6. Scope check: `remember` requires `memory:write` in the credential's
   `scopes`; a recall-only credential calling `remember` gets a
   domain-shaped `scope_denied` result (mirror
   `internal/server/memory/memory.go`'s `ErrCodeScopeDenied` envelope, not
   a bare HTTP 403 -- MEMORY_VERBS errors are protocol-layer JSON, not
   transport-layer status codes, per the existing tools' own error
   handling). Enforce this by inspecting the tool name in the parsed
   JSON-RPC request before delegating to the per-brain `HTTPHandler`, or
   by wrapping the `remember` tool's own `Handler` at registration time
   with a scope check closure -- either is acceptable; state which one was
   chosen in the PR.
7. Everything the per-brain `mcp.HTTPHandler` already does unmodified:
   `rejectedOrigin` (any `Origin` header rejected), `MCP-Protocol-Version`
   requirement, `DELETE` session teardown, `notifications/cancelled`
   cancellation, the 1 MiB frame cap (`MaxFrameBytes`). This task does not
   reimplement any of that; it wraps the existing `HTTPHandler` per brain.

Direction and disposition routes (`internal/cli/serve.go`'s
`runServeHTTP`, landed by T23.2) are never registered by this gateway.

### Acceptance criteria

- `tools/list` returns exactly `recall`, `remember`, `forget`,
  `read_memory_fact`.
- A request with one account's credential against a session id opened by
  a different account's credential is rejected 401 and that session is
  not reused for the caller.
- After `Rotate`, the next request on the already-established session
  using the old token is 401.
- `entity` and `synthesize` return JSON-RPC `-32602` (unknown tool), the
  same code `internal/server/mcp`'s own dispatcher already returns for an
  unregistered tool name.
- A recall-only credential calling `remember` gets `scope_denied`, not a
  generic failure.
- Genuine red: temporarily change step 4's comparison to always pass
  (skip the generation check), rerun the rotation test, and record that
  the old token's request wrongly succeeds on the established session.
  Restore the check and record the corrected 401. Report both outputs.

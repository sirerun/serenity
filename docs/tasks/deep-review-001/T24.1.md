## T24.1: Caddy: drop root, admin API on a 0600 unix socket, trusted_proxies with CF-Connecting-IP

Findings: SEC-H01, SEC-M03, ARC-M03 (edge half). Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees Caddy running as the `caddy` user with no TCP admin listener, reloads still working through the unix admin socket, and every app limiter keyed on the real client address because Caddy resolves it from Cloudflare's CF-Connecting-IP behind trusted_proxies. Live verification on the hosted host: `ss -ltnp | grep 2019` is empty, `sudo -u serenity curl -s localhost:2019/config/` is refused, `systemctl reload caddy` succeeds, and TLS is served by the migrated certificate (no new issuance in the Caddy log).

### Scope

May create or modify:

- deploy/hosted/caddy.service
- deploy/hosted/Caddyfile
- deploy/hosted/bootstrap.sh (create caddy user, /var/lib/caddy, /run/caddy, migrate /root/.local/share/caddy)
- deploy/hosted/deploy.sh (reload --address)
- deploy/hosted/tests/test_units.py (new)
- docs/launch/hosted-runbook.md (the migration step and the verification commands)

Out of scope:

- Application code under internal/ (the loopback header trust stays as is).
- deploy/hosted/stack.json (T23.54 owns it; the security-group change waits for T24.42).
- serenity-hosted.service and serenity-backup.service (T24.2).

### Acceptance criteria

- [ ] caddy.service has User=caddy, Group=caddy, AmbientCapabilities=CAP_NET_BIND_SERVICE, CapabilityBoundingSet=CAP_NET_BIND_SERVICE, NoNewPrivileges=yes, ProtectSystem=strict, ProtectHome=yes, PrivateTmp=yes, RuntimeDirectory=caddy, StateDirectory=caddy, XDG_DATA_HOME=/var/lib/caddy and XDG_CONFIG_HOME=/var/lib/caddy/config; ExecReload passes --address unix//run/caddy/admin.sock.
- [ ] Caddyfile begins with a global options block: admin unix//run/caddy/admin.sock|0600; the site block declares trusted_proxies static with Cloudflare's IPv4 and IPv6 ranges (source URL and fetch date in a comment), client_ip_headers CF-Connecting-IP, and header_up X-Serenity-Client-IP {client_ip}.
- [ ] bootstrap.sh creates the caddy system user and directories idempotently and, when /root/.local/share/caddy exists, copies it to /var/lib/caddy with chown -R caddy:caddy before enabling the unit.
- [ ] deploy/hosted/tests/test_units.py parses the three files and asserts every line above; it runs in CI (add to the existing python test job or the hosted test workflow).
- [ ] Live: on the hosted host after deploy, ss shows no listener on 2019, the admin socket is 0600 root-owned, `caddy reload` succeeds, the Caddy log shows no new certificate issuance, and `/readyz` returns 200. Record the outputs in the PR body.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body. For this task the red run is test_units.py failing against the current unit and Caddyfile.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

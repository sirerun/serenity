## T24.5: Quarantine a single unparsable page instead of failing the brain; audit non-conforming slugs

Findings: SEC-H03 (blast radius), FUN-03. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that one corrupt page can no longer take down retrieval, composition, the MCP entity tool or extraction for the whole brain: index.Rebuild, compose.AllClaims and the entity tool skip an unparsable page, record it in a quarantine list with the path and parse error, and continue. `serenity check` reports quarantined pages and any existing page whose slug does not satisfy domain.ValidSlug so an operator can rename before enforcement on read.

### Scope

May create or modify:

- internal/index/rebuild.go
- internal/compose/compose.go (AllClaims)
- internal/server/memory/entity.go
- internal/cli/check.go (quarantine and non-conforming slug report)
- matching _test.go files

Out of scope:

- The validator itself and boundary enforcement (T24.4).
- Automatic renaming of non-conforming pages.

### Acceptance criteria

- [ ] Rebuild, AllClaims and the entity tool each continue past a page whose frontmatter fails to parse; the failure is appended to a quarantine slice exposed to check and logged once with the path.
- [ ] serenity check prints a `quarantined pages` section and a `non-conforming slugs` section; the exit code follows ADR 010 (warning class).
- [ ] Test: a fixture brain with one page carrying a duplicate `type:` key and two good pages yields two indexed pages, one quarantine entry, and a successful AllClaims.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

### Verification

```sh
go test -race -count=1 ./internal/index ./internal/compose ./internal/server/memory ./internal/cli
```

## T24.2: App unit denies IMDS; backup unit has an OnFailure handler; deploy.sh rolls back on failed readiness

Findings: INF-03, INF-05 (unit and deploy halves). Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that a compromised application process cannot reach the instance metadata service (and therefore neither the Stripe secret nor the backup bucket), that a failed backup run triggers a named failure unit, and that a deploy whose readiness check fails restores the previous binary automatically instead of leaving the service down.

### Scope

May create or modify:

- deploy/hosted/serenity-hosted.service
- deploy/hosted/serenity-backup.service and a new serenity-backup-failed.service
- deploy/hosted/deploy.sh (keep previous binary, restore on readiness failure, shorten the readiness failure cache interaction)
- deploy/hosted/tests/test_units.py (extend)
- docs/launch/hosted-runbook.md (rollback behaviour)

Out of scope:

- stack.json alarms and SNS (T23.54 amendment).
- Caddy (T24.1).

### Acceptance criteria

- [ ] serenity-hosted.service has IPAddressDeny=169.254.169.254 and IPAddressAllow=localhost is NOT needed for outbound HTTPS (verify /readyz still reaches the embedder).
- [ ] serenity-backup.service keeps IMDS access and declares OnFailure=serenity-backup-failed.service, which logs to the journal and, once T23.54 lands, publishes to the alarm topic.
- [ ] deploy.sh: the previous binary is kept as <path>.prev; if `/readyz` is not 200 within the retry window the script restores it, restarts, and exits non-zero with `ROLLED BACK` in the output.
- [ ] Live: after deploy, `curl -s --max-time 2 http://169.254.169.254/` from a shell in the service's namespace (systemd-run --property=IPAddressDeny=...) is refused while `/readyz` returns 200. Record the outputs.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

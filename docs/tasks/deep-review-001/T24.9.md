## T24.9: Writer queue: recover a Render panic and return it as an error

Findings: CON-06. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that a panic inside any writer job cannot terminate the process (which on hosted takes every tenant down): drain recovers, converts the panic into an error carrying the job kind and a stack summary, returns it to that job's caller, and continues with the next job.

### Scope

May create or modify:

- internal/writer/queue.go
- internal/writer/queue_test.go

Out of scope:

- Any change to job ordering or the pending-record format (ADR 004).

### Acceptance criteria

- [ ] drain wraps job.Render in a recover that produces `writer: job <kind> panicked: <value>`; the job's result channel receives that error; the queue continues.
- [ ] Test: a Render that panics is followed by a job that succeeds; the subprocess test from the review (process terminates) is converted into an in-process assertion that the process survives.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

## T24.24: Source URIs carry repository-relative or hashed identifiers, never absolute paths

Findings: PRIV-03. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that a brain pushed to a remote no longer reveals the person's directory layout: file and git_repo sources record a connector-relative path (relative to the connector root) plus a stable hash of the absolute path for de-duplication; the absolute path lives only in the local index.

### Scope

May create or modify:

- internal/connector/file, internal/connector/gitrepo (source URI construction)
- internal/ingest (dedupe on the hash)
- internal/index (local absolute path column)
- tests; a migration note in docs/operator/

Out of scope:

- Existing brains' historical source records (a check warning lists them; no rewrite).

### Acceptance criteria

- [ ] New source records have `uri: <connector>:<relative>` and `path_hash`; a test asserts no `/Users/` or `/home/` substring in any committed source meta.
- [ ] Dedupe on re-sync still works across the change (same hash).
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

### Verification

```sh
go test -race -count=1 ./internal/connector/... ./internal/ingest ./internal/index
```

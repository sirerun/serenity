## T24.3: OAuth limiter: per-prefix buckets first, refresh grants exempt, consents capped per client

Findings: SEC-H02. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that no unauthenticated flood from a handful of addresses can switch off the OAuth authorization server for every tenant: limiting is per source prefix (/24 for IPv4, /56 for IPv6) and checked before any global window; the global ceiling applies only to unauthenticated state-creating paths (register, authorize) and is raised; refresh_token grants for known grants bypass the global window; live oauth_consents are capped per client_id, not per table.

### Scope

May create or modify:

- internal/hosted/oauth/ratelimit_test.go (new)
- internal/hosted/oauth/hosted.go (wire the limiter per path class)
- internal/hosted/oauth/store.go (per-client_id consent cap, eviction of expired consents on insert)

Out of scope:

- internal/hosted/gateway/admission.go (R-hosted-runtime; the shared limiter unification is T23.45's ARC-M03 step).
- The mcpoauth dependency version.

### Acceptance criteria

- [ ] prefixKey masks IPv4 to /24 and IPv6 to /56; the per-key bucket is evaluated before the global counter.
- [ ] The global counter covers only POST /oauth/register and GET|POST /oauth/authorize and its limit is at least 10x the per-key limit; /oauth/token with grant_type=refresh_token whose refresh token resolves to a known grant is never refused by the global counter.
- [ ] store.go refuses a new consent only when the same client_id has 500 live consents; inserting a consent first evicts that client's expired consents; the 10000-row table cap no longer applies to oauth_consents.
- [ ] ratelimit_test.go covers: the 17-address scenario (refresh from an 18th admitted); one IPv6 /64 rotation counting as one key; the consent cap per client_id; the existing TestOAuthBrowserConsentMCPAndRevocation stays green.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.

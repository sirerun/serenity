## T24.42: Confirm the ACME challenge path and record it as evidence for the origin lock-down

Findings: INF-02 prerequisite, SEC-M03. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

Whoever holds the live operator lease reads the Caddy log on the hosted host (read-only) to record which ACME challenge issued the current certificate, tests a forced renewal in a staging window with the origin temporarily reachable only from Cloudflare ranges (or records that DNS-01 or a Cloudflare origin certificate is the path), and writes the finding so T23.54 can restrict the security group without breaking issuance.

### Scope

May create or modify:

- docs/launch/evidence/E24/acme-path.md (new)

Out of scope:

- stack.json (T23.54 applies the change).
- Any DNS change (foundation repo).

### Acceptance criteria

- [ ] The evidence file names the challenge type, the log lines (sanitized), the renewal outcome under the restricted condition, the Cloudflare range source URL and fetch date, and a recommendation among HTTP-01 through the proxy, DNS-01 with a scoped Cloudflare token, or a Cloudflare origin certificate.
- [ ] No mutating change is made to the running host beyond the reversible test window, and the window is recorded with start and end times.

### Verification

```sh
journalctl -u caddy --no-pager | grep -i 'obtain\|challenge\|renew'   # on the host, read-only
```

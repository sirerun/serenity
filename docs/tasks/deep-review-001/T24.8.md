## T24.8: Config trust: KnownFields, connector path containment, loopback bind unless allow_lan

Findings: SEC-H05 (config half). Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that a serenity.yml delivered through the brain remote cannot point the process at an arbitrary repository, bind the daemon to the LAN, or smuggle unknown keys: config.Load uses KnownFields(true) and names the first unknown key; connector paths resolve to absolute cleaned paths under the home directory or an explicit `connectors.roots` allowlist; `server.bind` must be loopback unless `server.allow_lan: true`.

### Scope

May create or modify:

- internal/config/config.go, config_test.go (KnownFields, typed connectors, roots)
- internal/cli/connectorbuild.go and its tests (containment)
- internal/cli/serve.go and its tests (bind check)
- docs/operator/ config reference for the two new keys

Out of scope:

- The git runner (T24.7).
- Connector trust levels (T24.16).

### Acceptance criteria

- [ ] config.Load returns an error `unknown key <path>` for any unrecognized key at any level; golden decodes in config_test.go are updated to strict form.
- [ ] connectorbuild resolves `path` with filepath.Abs and Clean and requires it under one of the roots (home by default); an escaping path fails with the path named.
- [ ] serve refuses a non-loopback bind without allow_lan and logs the refusal.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

### Verification

```sh
go test -race -count=1 ./internal/config ./internal/cli
```

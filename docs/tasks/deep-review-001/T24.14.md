## T24.14: Output neutralizer: strip control sequences on every print and drop URLs absent from evidence

Findings: AI-05, SEC-M05. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees one helper (`internal/neutralize`) that removes C0/C1 control characters and ESC sequences, applied at every CLI print of ingested or model text and at the MCP synthesize output, and a composer step that removes any URL the model emitted that did not appear in the retrieved evidence, so a planted image link cannot exfiltrate co-resident claims through a rendering client.

### Scope

May create or modify:

- internal/neutralize/neutralize.go, _test.go (new)
- internal/compose/compose.go (sanitizeText extended with the evidence-URL allowlist)
- internal/server/memory/synthesize.go
- internal/cli/ask.go, search.go, inbox.go (every print of untrusted text)

Out of scope:

- Markdown rendering choices of MCP clients.
- Terminal width or colour handling.

### Acceptance criteria

- [ ] neutralize.Text removes ESC (0x1b) sequences (CSI, OSC with ST or BEL terminators), C0 except \n and \t, and C1; a table test covers the review's hide-and-spoof payload.
- [ ] compose: URLs in the answer that are not byte-equal to a URL present in the retrieved evidence are replaced by `[link removed]`; citations are unaffected.
- [ ] Every listed CLI print site passes through neutralize.Text (a test greps the print sites or exercises each command with a payload).
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

### Verification

```sh
go test -race -count=1 ./internal/neutralize ./internal/compose ./internal/server/memory ./internal/cli
```

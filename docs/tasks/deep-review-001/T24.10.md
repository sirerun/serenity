## T24.10: Release hygiene: .env ignored, write token on the publish job only, pinned goreleaser, no tidy at release

Findings: SEC-INF-SECRET, SUP-02, SUP-01 (part). Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that the test job in the release workflow cannot write to the repository, that the release build is reproducible against a pinned goreleaser without mutating go.mod at release time, and that a local .env can never be committed.

### Scope

May create or modify:

- .gitignore
- .github/workflows/release.yml
- .goreleaser.yaml
- .github/workflows/ci.yml only if the goreleaser version pin needs a matching install step

Out of scope:

- SHA-pinning of actions, scanners, signing and SBOM (T24.11).
- Renaming the sk_live_ credential prefix (hosted credential package, R-hosted-runtime; deferred to T24.40).

### Acceptance criteria

- [ ] .gitignore contains a `.env` line and `git check-ignore .env` succeeds.
- [ ] release.yml: workflow-level permissions are contents: read; the adversarial-gate job has no write permission; only the publish job declares contents: write.
- [ ] .goreleaser.yaml: the `before.hooks` no longer runs go mod tidy; the workflow installs goreleaser at an exact version (`vX.Y.Z`) rather than `~> v2`.
- [ ] A dry run (`goreleaser release --snapshot --clean --skip=publish`) succeeds locally.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body. For this task the red run is `git check-ignore .env` failing and a workflow-permissions grep showing write at workflow scope.
- [ ] actionlint on the workflow passes.

### Verification

```sh
git check-ignore -v .env
actionlint .github/workflows/release.yml
goreleaser release --snapshot --clean --skip=publish
```

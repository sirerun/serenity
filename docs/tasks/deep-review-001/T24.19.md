## T24.19: Adversarial release gate runs the corpus through the real extract and compose pipeline; scanners cover pkg/ and cmd/

Findings: AI-L01. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees a release gate that would have caught SEC-H03: every adversarial corpus document is fed through the real extraction and composition code with a scripted provider that returns the corpus's intended hostile output, and the gate asserts no file name, frontmatter key, precept or URL escapes containment; the AST scanners cover pkg/ and cmd/ as well as internal/; the `SERENITY_ADVERSARIAL_VULNERABLE=1` switch seeds a real vulnerability (validator disabled) rather than a bare Fatalf.

### Scope

May create or modify:

- internal/gate/adversarial_corpus_test.go and helpers
- evals/adversarial/ corpus additions (subject injection, markdown exfil, terminal escape)
- .github/workflows/release.yml gate step (unchanged invocation)

Out of scope:

- The corpus's human-review labels (ADR 005).

### Acceptance criteria

- [ ] The scripted provider path exists and is used for every corpus document; a test proves the gate fails with the validator disabled and passes with it enabled.
- [ ] Scanner coverage includes pkg/ and cmd/ and the test lists the scanned roots.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.
- [ ] gofmt -l ./internal ./cmd ./pkg (empty), go vet ./..., golangci-lint run on the changed packages under the build lease.

### Verification

```sh
go test -race -count=1 ./internal/gate
SERENITY_ADVERSARIAL_VULNERABLE=1 go test -count=1 ./internal/gate   # expect failure
```

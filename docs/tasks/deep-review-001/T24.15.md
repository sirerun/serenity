## T24.15: Disposition actor from the transport principal; precepts accepted only through the CLI; no provider error echo

Findings: AI-03, AI-L02. Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees that no agent can forge human authority: the disposition and direction HTTP handlers derive the actor from the authenticated principal and ignore the wire field; a precept_draft can only be accepted with a human actor, which only the CLI channel produces; inbox --apply shows the full payload before publishing a precept; provider error bodies are mapped to a status code for check_plan. The stale `not wired` package documentation is corrected.

### Scope

May create or modify:

- internal/server/disposition/disposition.go (actor derivation)
- internal/server/direction/direction.go (actor, error mapping)
- internal/cli/serve.go (principal plumbing, package doc)
- internal/direction/publication.go (require human actor and CLI origin for precepts)
- internal/cli/inbox.go (print payload, refuse non-CLI precept accepts)
- docs/protocol/DISPOSITION_v1.md and DIRECTION_v1.md (actor is advisory on the wire)
- tests in each package

Out of scope:

- Hosted gateway (the four public tools do not expose disposition).
- The dira ledger format (ADR 008).

### Acceptance criteria

- [ ] handleDispose sets actor to `agent:<credential id>` for bearer callers regardless of req.Actor; a test proves human:david on the wire is recorded as agent:<id>.
- [ ] publication refuses a precept_draft whose actor is not `human:` or whose origin is not the CLI channel; the HTTP path therefore returns forbidden for precept acceptance.
- [ ] inbox --apply prints kind, target and the full body of a precept before publishing and requires the CLI's own actor.
- [ ] check_plan maps provider errors to `provider_error` with a status code and no body.
- [ ] Protocol docs updated; the serve package doc no longer says the routes are unwired.
- [ ] Genuine-red requirement: before the fix, add the new test and run it against the unchanged code; record the predicted failure output. Then apply the fix and record the green output. Both outputs go in the PR body.

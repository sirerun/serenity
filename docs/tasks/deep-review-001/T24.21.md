## T24.21: Forget and source tombstone delete index rows and working-tree bytes in the same flush

Findings: PRIV-01 (tree and index). Plan row: `docs/plans/deep-review-001-remediation.md`.

### Objective

A reviewer sees the first two of the three erasure targets closed: on forget the fact directory is removed from the working tree and its FTS and vector rows are deleted in the same flush (expired facts likewise drop their rows on rebuild); `store.Tombstone` is implemented for sources and removes bytes and meta. The expiry event stays as the audit record and never carries the fact text.

### Scope

- internal/writer/memoryfact.go (forget removes the directory)
- internal/index/rebuild.go (drop rows for forgotten and expired facts)
- internal/store/source.go (Tombstone real implementation)
- tests

Out of scope:

- History rewrite (T24.22).
- Hosted export and deletion (T23.48).

## T23.9: Identity: magic link, sessions, logout, CSRF, rate limits

### Objective

A reviewer sees email-only signup/login: requesting a link sends one
message through a `Sender` interface, the link is single-use and expires
in 15 minutes, a valid click sets a secure session cookie, every
state-changing dashboard request is CSRF-checked, and repeated requests
for one address are rate limited.

### Scope

Create `internal/hosted/identity/` only: `identity.go` (`Service`,
`RequestLink`, `Consume`, `Logout`, session/CSRF helpers), `resend.go`
(the `Sender` implementing the Resend HTTP API), `identity_test.go`.
Depends on `internal/hosted/store` (T23.4) for `login_tokens` and
`sessions`. Out of scope: no HTTP routing/handlers (T23.10's dashboard
wires this service into routes); no dashboard HTML; no credential or
brain provisioning logic (T23.5, T23.6 own those, called by T23.10 after
login, not by this package).

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/identity`.

`Sender interface { Send(ctx context.Context, to, link string) error }`.
`resend.go` implements it over `https://api.resend.com/emails` with
`RESEND_API_KEY` read from the hosted secrets directory (T23.11 defines
that directory; this package accepts the key as a plain string parameter
so it has no dependency on T23.11's config loader) and a `From` address of
`login@serenity.sire.run`. Tests use an in-memory `Sender` that records
calls instead of hitting the network. A `DevSender` prints the link via a
supplied `io.Writer` -- wired to stderr only when `SERENITY_HOSTED_DEV=1`
and the bind address is loopback (T23.11's own responsibility to check the
bind address before choosing this sender; this package just provides it).

`Service{Store *hoststore.Store, Sender Sender, Clock func() time.Time}`.

- `RequestLink(ctx, email string) error`: generates 256 random bits
  (`crypto/rand`, 32 bytes), stores `hex(sha256(token))` in
  `login_tokens.token_hash` with `expires_at = now + 15m`, calls
  `Sender.Send` with a URL embedding the raw token
  (`https://app.serenity.sire.run/login/consume?token=<raw>`). Always
  returns success regardless of whether the address has an account yet
  (the response never reveals whether an address is known -- ADR 015).
  Rate limit: at most 5 successful `RequestLink` calls per email and per
  IP per rolling minute; the 6th and later return success to the caller
  (no enumeration signal) but do not send mail and do not insert a new
  `login_tokens` row -- the epic's own acc line ("six link requests ...
  return 429 on the sixth") means the HTTP layer built in T23.10 is what
  returns 429 by checking a counter this service exposes
  (`TooManyRequests(email, ip string) bool`), since a bare `RequestLink`
  call has no HTTP status to return; document this split in the PR.
- `Consume(ctx, rawToken string) (accountID string, err error)`: hashes
  the token, looks it up, checks `expires_at` and `consumed_at IS NULL`,
  marks it consumed in the same transaction it reads it in (single-use),
  and creates the account row via `CreateAccount` if the email has none
  yet (signup and login are the same action -- ADR 015). A second
  `Consume` of the same raw token returns `ErrExpiredOrUsed`.
- `StartSession(ctx, accountID string) (rawSessionToken string, err error)`:
  256 random bits, `sha256` hash stored in `sessions.token_hash`,
  `expires_at = now + 30d`. The caller (T23.10) sets it as a cookie
  `Secure; HttpOnly; SameSite=Lax`, host-only on `app.serenity.sire.run`.
- `Logout(ctx, rawSessionToken string) error`: deletes the session row.
- `CSRFToken(sessionID string) string` and `CheckCSRF(sessionID, submitted string) bool`:
  derive the CSRF token from the session's own `csrf_secret` column
  (e.g. `hex(hmac.New(sha256.New, []byte(csrfSecret)).Sum(nil))`) so it
  need not be stored separately; T23.10's forms embed it as a hidden
  field and the dashboard's mutation routes reject a missing or mismatched
  token with 403, and additionally check `Sec-Fetch-Site`/`Origin` when
  present.

### Acceptance criteria

- `POST /login` with an email sends one message through `Sender`
  containing a link that, when opened once, sets a
  `Secure; HttpOnly; SameSite=Lax` cookie and creates the account.
  (This task provides `RequestLink`/`Consume`/`StartSession`; the actual
  `POST /login` route is T23.10's, exercised there against this service.)
- Opening the same link a second time returns `ErrExpiredOrUsed` from
  `Consume` (T23.10 renders this as the expired-link page).
- A `CheckCSRF` call with a mismatched or missing token fails.
- The sixth `RequestLink`-eligible request for one email inside a minute
  is reported by `TooManyRequests` as rate-limited.
- `Logout` deletes the session row; a subsequent lookup of that session
  token fails.
- Genuine red: change `Consume`'s update to not set `consumed_at` (only
  read the row, never mark it used), rerun the single-use test, and record
  that the same raw token succeeds twice. Restore the update and record
  that the second call returns `ErrExpiredOrUsed`.

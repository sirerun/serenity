## T23.8: Brain runtime pool

### Objective

A reviewer sees a bounded LRU pool of open brain runtimes: with a cap of
two, opening a third evicts the idle one and reopens it on demand with
its data intact; a fourth concurrent open beyond the in-flight cap fails
fast with a typed capacity error instead of blocking; every open brain is
held under the single-writer lock PR 221 introduces.

### Scope

Create `internal/hosted/pool/` only: `pool.go` (`Pool` type, `Open`,
`Close`, eviction), `pool_test.go`. Depends on `internal/hosted/provision`
(T23.5) for brain directory paths and on the existing `internal/providers`,
`internal/writer`, `internal/store`, `internal/embed`, `internal/config`
packages to open a brain's runtime the same way
`internal/cli/serve.go`'s `memoryTools` already does. Out of scope: no
HTTP (T23.7 calls `Pool.Open`, this task does not serve requests); no
credential or session logic; does not modify `internal/providers`,
`internal/writer`, `internal/store`, or `internal/index` -- it only calls
their existing exported constructors.

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/pool`.
`Config{MaxOpen, MaxInFlight int, IdleTimeout time.Duration, BrainsRoot string}`.
`Pool{cfg Config, mu sync.Mutex, open map[string]*runtime, inFlight int32}`
where `runtime` bundles exactly what `memoryTools` (`internal/cli/serve.go:178-231`)
already assembles per brain: `*index.SQLite` (via `providers.OpenIndex`),
`*writer.Queue` (`writer.NewQueue(nil)`), an `embed.Embedder` (via
`providers.BuildEmbeddingRouter`), a `compose.Completer` (via
`providers.BuildComposerRouter`), and the `memory.Deps` built from them --
this task reuses those exact constructors rather than duplicating the
brain-opening logic `memoryTools` already contains.

`Open(ctx, brainID string) (*Runtime, error)`:

1. `p.mu.Lock()`; if `brainID` is already open, bump its LRU position,
   return it.
2. If `len(p.open) >= MaxOpen`, evict the least-recently-used idle entry
   (close its queue and index the same way `memoryTools`'s `closeDeps`
   does: `q.Close()`, `writer.Flush(q, root)`, `eng.Close()`) before
   opening the new one. "Idle" for eviction purposes means not currently
   serving an in-flight tool call (track a per-runtime in-flight counter;
   never evict a runtime with a nonzero counter).
3. If accepting the new open would exceed `MaxInFlight` concurrent
   in-flight tool calls across the whole pool, return a typed
   `ErrCapacity` immediately (`errors.New` sentinel, or a small struct if
   a retry-after hint is useful) -- never block waiting for capacity; the
   epic's own acc line requires this to resolve within 100 ms, so this is
   a fail-fast admission check, not a semaphore wait.
4. Open the brain via `providers.OpenIndex(path)`, construct the writer
   queue and embed/compose routers exactly as `memoryTools` does, hold
   the result under `p.open[brainID]`, release the lock.

Single-writer enforcement: PR 221 (landed by T23.1) introduces a
process-owner lock over a brain's canonical files; this task's own scope
is to acquire and hold that lock for the lifetime of each open runtime
entry (one lock per open brain, released on eviction/`Close`) and to
never open the same `brainID` twice concurrently -- the pool's own
`p.open` map already guarantees at most one runtime per brain id, which
is what makes holding one lock per entry sufficient. The exact lock type
and acquire/release method names are PR 221's to name; reference them by
grep once that PR has merged rather than assuming a name here, since PR
221 has not yet landed as of this task's authoring.

`Close()` evicts and closes every open runtime, joining in-flight calls
first (same posture as `mcp.HTTPHandler.Close`, `internal/server/mcp/http.go:111-117`).

### Acceptance criteria

- With `MaxOpen=2`, opening three brains evicts the idle one and re-opens
  it on demand with its data intact (write a fact, force eviction by
  opening two more brains, reopen the first, `recall` finds the fact).
- A fourth concurrent open beyond `MaxInFlight` returns `ErrCapacity`
  within 100 ms instead of blocking.
- The process-owner lock from PR 221 is held for every open brain (once
  PR 221 has merged and its lock API is known, assert it is acquired on
  open and released on eviction/close; until then, this criterion is
  blocked on T23.1 and must not be silently skipped -- flag it in
  `hosted-status.md` if T23.8 starts before T23.1 lands).
- Genuine red: set `MaxOpen` to 1 but skip the eviction step (return an
  error instead of evicting), rerun the three-brain test, and record that
  the second `Open` call fails instead of evicting the idle first brain.
  Restore eviction and record the corrected pass.

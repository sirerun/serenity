## T23.11: `serenity hosted serve`, config and readiness

### Objective

A reviewer runs `serenity hosted serve --config <file>` and sees it refuse
to start with a named missing secret file, an unauthenticated `/healthz`
that is always 200, and a `/readyz` that is 503 until migrations are
applied and a real embeddings call succeeds, then 200. No token ever
appears in any log line at any level.

### Scope

Create `internal/hosted/config/` (`Config` type, `Load`),
`internal/hosted/hostedlog/` (structured JSON logging with a shared
redaction hook), and add a new `hosted` subcommand under `internal/cli/`
(`internal/cli/hosted.go`, `internal/cli/hosted_serve.go`) that wires
`internal/hosted/store`, `internal/hosted/provision`,
`internal/hosted/credential`, `internal/hosted/pool`,
`internal/hosted/gateway`, `internal/hosted/identity`,
`internal/hosted/dashboard`, and `internal/hosted/identity`'s `resend.go`
sender together behind one `http.ServeMux`. Out of scope: does not modify
`internal/server` or `internal/server/mcp` (this command builds its own
top-level listener, it does not call `internal/server.New`, since that
type always authenticates `/healthz` with a single daemon token --
see Design notes); no CloudFormation or deploy scripting (T23.13, T23.14).

### Design notes

`internal/hosted/config.Config` fields: `Bind` (loopback-only in hosted
mode; Caddy fronts it, matching ADR 014's topology), `DataDir` (parent of
`brains/` and `control.db`), `SecretsDir` (root-only directory, mode
`0700`, populated from AWS Secrets Manager at boot by infra outside this
task's scope), `PublicOrigin` (`https://app.serenity.sire.run`),
`PlanVersion`, and pool caps (`MaxOpenBrains`, `MaxInFlight`). `Load(path
string) (*Config, error)` parses YAML the same way `internal/config.Load`
parses `serenity.yml` (`internal/config/config.go:149-159`), a distinct
file since hosted config has nothing to do with a single brain's
`serenity.yml`.

Required secret files under `SecretsDir`: `resend_api_key`,
`stripe_secret_key`, `stripe_webhook_secret`, `embeddings_api_key`,
`session_signing_key` (matches the Secrets Manager entry names T23.13
will create). At startup, before binding, check each file exists and is
readable; missing any one is a hard startup failure naming which file
by name (never printing its would-be content). Wave-0/1 tasks only need
`resend_api_key` and `embeddings_api_key` to be genuinely required (Stripe
keys are wave-3, T23.16/T23.21); if this task lands before those wave-3
secrets are named in infra, gate the Stripe/session-key checks behind a
config flag so the slice can start without them, and say so plainly in
the PR rather than silently hardcoding placeholders.

`internal/hosted/hostedlog`: one JSON log encoder (`encoding/json` over
`log/slog`, Go's standard structured logger, already available in this
module's Go 1.26 toolchain) with a redaction `slog.Handler` wrapper that
rejects (replaces with `"[redacted]"`) any log attribute whose key
matches a small denylist (`token`, `bearer`, `secret`, `session_id`,
`email`, `fact`) case-insensitively -- every package under
`internal/hosted` that logs must use this shared logger, not `fmt.Println`
or a bare `log.Printf`, so the redaction is structural rather than
per-call-site discipline.

`internal/cli/hosted.go` adds `serenity hosted serve --config <file>` as
a sibling cobra command to the existing `serve` command
(`internal/cli/serve.go:28-50`), not a flag on it -- hosted mode has a
materially different binding chain (ADR 014) and does not share
`runServeHTTP`'s single-brain, single-token model. Build one
`http.ServeMux` registering: `/healthz` (unauthenticated, always 200, no
`internal/server.Server` wrapping since that type cannot express an
unauthenticated route), `/readyz` (unauthenticated; checks
`schema_migrations` is at the current version, every required secret file
was read successfully at boot, a real bounded embeddings call succeeds
against the pinned model, and `DataDir/brains` is writable -- 503 until
all pass, then 200), `/mcp` (the gateway, T23.7, credential-authenticated
per request, not by this mux), and the identity/dashboard routes (T23.9,
T23.10, cookie-authenticated).

### Acceptance criteria

- `serenity hosted serve --config <file>` starts with secrets read from
  files under a directory whose mode is `0700`, and refuses to start if
  any required secret file is missing, naming which one by filename.
- `GET /healthz` is 200 unauthenticated.
- `GET /readyz` is 503 until migrations are applied and a real bounded
  embeddings call succeeds, then 200.
- No token, session id, email, or fact text appears in any log line at
  any level -- a log-capture test running the full startup and one
  authenticated request set asserts this against every emitted line.
- Genuine red: temporarily bypass the redaction handler (log directly with
  the standard `slog.NewJSONHandler`, no wrapper) for one call site that
  logs the raw bearer token on an auth failure, rerun the log-capture
  test, and record that it now fails because the token appears verbatim.
  Restore the redacting handler and record the corrected pass.

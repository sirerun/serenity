## T23.4: Control database and hosted store

### Objective

A reviewer sees a new `internal/hosted/store` package: applying its
migrations to an empty SQLite file produces every table ADR 014 requires,
a two-account fixture proves one account can never read another's brain
row, and a credential-prefix lookup resolves to the bound (account, brain,
generation, scopes). No HTTP, no provisioning state machine, no
credential-issuing logic -- those are T23.5, T23.6, T23.9. This task owns
the schema and the minimal read/write primitives those later tasks build
on.

### Scope

Create `internal/hosted/store/` only: `store.go` (Open, Store type, error
sentinels), `migrations.go` (embedded SQL migrations and the apply
function), and `store_test.go`. May also add `.sql` files under
`internal/hosted/store/migrations/`. Out of scope: no HTTP handlers, no
provisioning, no credential issuance/rotation logic (only the row shapes
and a lookup they need), no Stripe/webhook code, nothing under
`internal/store`, `internal/writer`, `internal/index`, or `internal/server`.

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/store`. Driver:
blank-import `modernc.org/sqlite` exactly as `internal/index/sqlite.go`
does (`_ "modernc.org/sqlite"` plus `database/sql`), since that driver is
already a pinned dependency (go.mod: `modernc.org/sqlite v1.57.0`) and no
new third-party dependency is allowed this wave.

`Open(path string) (*Store, error)` opens the DB and applies every
pending migration in order inside a transaction, recording each version in
`schema_migrations(version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL)`.
Single-writer discipline (ADR 014, epic acc line): the simplest
standard-library realization is `db.SetMaxOpenConns(1)` on the one
`*sql.DB`, so the connection pool never opens a second connection and
`SQLITE_BUSY` from concurrent writers cannot occur; open the DSN with
`?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)`
(modernc.org/sqlite's own `_pragma=` DSN convention) as the epic's named
WAL + busy_timeout requirement. Every mutation runs inside `db.BeginTx`
with immediate commit or rollback; no bare `Exec` outside a transaction for
a multi-statement write.

Tables, columns exactly as the epic names them for the three it specifies:

- `accounts(id TEXT PRIMARY KEY, email_hash TEXT NOT NULL UNIQUE, email TEXT NOT NULL, created_at TEXT NOT NULL, status TEXT NOT NULL, plan_id TEXT NOT NULL, plan_version INTEGER NOT NULL, stripe_customer_id TEXT)`.
  `email_hash` is SHA-256 hex of the lowercased address, used for lookup;
  `email` is stored for sending mail but is never logged (see the
  redaction hook T23.11 builds; this task just avoids `fmt.Println`/log
  calls that would include it).
- `brains(id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id), state TEXT NOT NULL, path_key TEXT NOT NULL, created_at TEXT NOT NULL, ready_at TEXT, deleted_at TEXT)`.
  `state` is one of `allocating`, `ready`, `deleted` (T23.5 owns the
  transitions; this task only stores the column and an index on
  `(account_id, state)`).
- `client_credentials(id TEXT PRIMARY KEY, brain_id TEXT NOT NULL REFERENCES brains(id), account_id TEXT NOT NULL REFERENCES accounts(id), prefix TEXT NOT NULL UNIQUE, verifier TEXT NOT NULL, scopes TEXT NOT NULL, generation INTEGER NOT NULL, created_at TEXT NOT NULL, revoked_at TEXT)`.
  `scopes` is a comma-joined string (`memory:read`, `memory:write`);
  `verifier` is the hex SHA-256 of the raw secret, never the raw secret
  itself (T23.6 owns hashing and generation logic).

Tables the epic names without columns; this task's own minimal design so
later tasks have a place to write, not a frozen contract for their
behavior (T23.9 may add columns to `login_tokens`/`sessions` in its own PR
if the shape here proves insufficient):

- `login_tokens(id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id), token_hash TEXT NOT NULL UNIQUE, created_at TEXT NOT NULL, expires_at TEXT NOT NULL, consumed_at TEXT)`.
- `sessions(id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id), token_hash TEXT NOT NULL UNIQUE, created_at TEXT NOT NULL, expires_at TEXT NOT NULL, csrf_secret TEXT NOT NULL)`.
- `usage_windows(account_id TEXT NOT NULL, window_key TEXT NOT NULL, metric TEXT NOT NULL, committed INTEGER NOT NULL DEFAULT 0, PRIMARY KEY (account_id, window_key, metric))`.
- `reservations(id TEXT PRIMARY KEY, account_id TEXT NOT NULL, window_key TEXT NOT NULL, metric TEXT NOT NULL, amount INTEGER NOT NULL, operation_key TEXT, status TEXT NOT NULL, lease_expires_at TEXT, created_at TEXT NOT NULL)`.
- `stripe_events(id TEXT PRIMARY KEY, received_at TEXT NOT NULL, processed_at TEXT)`.
- `subscriptions(id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id), price_id TEXT NOT NULL, status TEXT NOT NULL, current_period_end TEXT, cancel_at_period_end INTEGER NOT NULL DEFAULT 0)`.
- `audit_log(id INTEGER PRIMARY KEY AUTOINCREMENT, account_id TEXT, actor TEXT NOT NULL, action TEXT NOT NULL, created_at TEXT NOT NULL, detail TEXT)`.

Go accessors this task must provide (names are this task's own choice,
the epic does not name them):

- `CreateAccount(ctx, email string) (Account, error)`.
- `InsertBrain(ctx, accountID, brainID, pathKey, state string, now time.Time) (Brain, error)` --
  used by T23.5's state machine; this task does not implement the
  allocating-to-ready transition itself.
- `BrainByID(ctx, accountID, brainID string) (Brain, error)` -- the query
  is `WHERE id = ? AND account_id = ?`; a brain id that exists under a
  different account returns `ErrNotFound`, never the row. This is the
  acceptance line's two-account isolation check.
- `InsertCredential(ctx, cred ClientCredential) error`.
- `CredentialByPrefix(ctx, prefix string) (CredentialBinding, error)`
  returning `{AccountID, BrainID, Generation string/int, Scopes []string,
  RevokedAt *time.Time}` -- `ErrNotFound` when the prefix is unknown.

`ErrNotFound` is a package-level sentinel (`errors.New`), matching the
pattern `internal/secrets.ErrNotFound` already uses for the same shape of
"absent, not a system error" result.

### Acceptance criteria

- `go test ./internal/hosted/store/...` passes with migrations applied to
  an empty SQLite file, a two-account fixture proves `BrainByID` returns
  `ErrNotFound` for the other account's brain id, and a credential lookup
  by prefix returns the bound (account, brain, generation, scopes).
- `schema_migrations` records every applied version exactly once; running
  `Open` a second time against the same file applies nothing new and
  produces no error.
- Every mutating accessor runs inside a transaction; a test that injects a
  failure mid-transaction (e.g. a second write that violates a UNIQUE
  constraint) leaves no partial row behind.
- Genuine red: comment out the `AND account_id = ?` clause in `BrainByID`'s
  query, rerun `go test ./internal/hosted/store/... -run TestBrainByID
  -v`, and record the failing output (the other account's brain id
  resolves instead of returning `ErrNotFound`). Restore the clause and
  record the passing output.

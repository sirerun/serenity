## T23.10: Dashboard v1: Connect Rakazo

### Objective

A reviewer logs in for the first time and sees exactly one brain already
in `ready` state with no click required, a Connect page with the HTTPS
endpoint, a one-time-displayed raw token with a copy button, and the four
fields Rakazo's own settings form expects. "Connected" and "First memory
saved" indicators light up only after the server observes a real
`tools/list` and a real `remember` against that credential, not from
client-side state.

### Scope

Create `internal/hosted/dashboard/` only: `dashboard.go` (route
registration and handlers), `templates/*.html` (`html/template`
templates), `static/connect.js` (copy-button and status-polling script).
Depends on `internal/hosted/identity` (T23.9), `internal/hosted/provision`
(T23.5), `internal/hosted/credential` (T23.6), and reads brain fact counts
through the same write path MCP uses (`internal/server/memory`, read-only,
via a small helper this task adds inside `internal/hosted/dashboard`, not
by modifying `internal/server/memory`). Out of scope: no gateway/MCP
transport code (T23.7 owns that); no billing UI (T23.23); no changes to
`internal/server/memory` beyond the `ToolsNamed` seam T23.7 already adds.

### Design notes

Package `github.com/sirerun/serenity/internal/hosted/dashboard`. Server-
rendered `html/template`, no JS framework; one small vanilla script
(`static/connect.js`) for the copy-to-clipboard button and periodic
polling of an authenticated JSON status route. Responsive at 400 px
width (no fixed-width layout wider than the viewport).

Routes (mounted by T23.11's `serenity hosted serve` alongside the gateway
and identity routes):

- `GET /login`, `POST /login` (calls `identity.Service.RequestLink`),
  `GET /login/consume` (calls `Consume` then `StartSession`, sets the
  cookie, redirects to `/`).
- `GET /` (authenticated via session cookie): calls
  `provision.Provisioner.Provision(ctx, accountID)` to ensure the
  account's one brain exists and is `ready`, then renders it -- this is
  the "without any click" requirement; provisioning happens as a side
  effect of loading the dashboard, not behind a button.
- `GET /connect`: shows the HTTPS MCP endpoint
  (`https://app.serenity.sire.run/mcp`), a button that calls
  `credential.Issuer.Issue` server-side and renders the raw token once in
  the response body with a copy control (never stored client-side beyond
  that single page load), and the four fields Rakazo's settings form
  needs, per the epic's discovery of the real adapter: MCP endpoint,
  bearer token, brain label (empty label is the documented default), and
  the "Recall only" / "Recall and write" toggle (default: recall only,
  meaning `Issue` is called with `scopes = ["memory:read"]` unless the
  user opts into write, `["memory:read", "memory:write"]`).
- `GET /connect/status` (authenticated JSON, polled by `connect.js`):
  reports `connected` (true once the gateway, T23.7, has observed a
  `tools/list` call using this brain's credential -- track this as a
  `last_seen_at`-style column update the gateway makes on successful
  `tools/list`, or a small counter this task adds to `client_credentials`
  via a migration in its own PR, coordinated with T23.7's PR to avoid a
  duplicate column) and `first_memory_saved` (true once a `remember` has
  succeeded for this brain -- same tracking approach).
- `POST /memories` (authenticated, CSRF-checked): creates one memory
  through the exact same write path MCP's `remember` uses
  (`internal/server/memory`'s `Handlers.remember`, invoked here via a
  `Handlers` instance this task constructs the same way T23.8's pool
  does, or by delegating to the pool's already-open runtime for that
  brain) so the dashboard's "current fact count" and the account's usage
  counters never disagree with what MCP wrote.

Every mutation route (`POST /login`, `POST /memories`, credential
issue/rotate) checks `identity.Service.CheckCSRF` before doing anything.

### Acceptance criteria

- After first login the dashboard shows exactly one brain in `ready`
  state without any click.
- The Connect page shows the HTTPS endpoint, the raw token once with copy
  controls, and the four Rakazo settings-form fields.
- "Connected" appears only after the server records a `tools/list` with
  that credential, and "First memory saved" only after a successful
  `remember` -- both observed server-side, not inferred from the client
  having loaded the Connect page.
- A Playwright test covers the golden path (login link -> dashboard shows
  ready brain -> Connect page shows token -> status flips to connected
  after a real `tools/list`) and the expired-link edge (`Consume` on a
  reused link renders the expired-link page, not a generic error).
- Viewing fact count and creating one memory from the dashboard use the
  same write path as MCP, so status and quota numbers agree.
- Genuine red: change `POST /memories` to call a hypothetical separate
  write path instead of `Handlers.remember` (or, concretely, skip the
  `Handlers.remember` call and write a row with a different dedup key
  scheme), rerun a test that creates a memory from the dashboard and then
  recalls it over MCP, and record that it fails to appear (or double-
  counts). Restore the shared path and record the corrected pass.

## Required steps

Fetch provider truth for the server-owned customer and atomically update entitlements; reject unknown prices/customer mismatch without granting paid access. Reconciliation must support restore_pending rows without activation and replace stale subscriptions/checkout attempts after authoritative resolution.
2. Implement CloseBillingAccount for a durable deleting account: stop new checkout, expire pending sessions, list/cancel provider subscriptions even if the creation webhook never arrived, recheck until closure is known. Resume after ambiguous provider success and local timeout.
3. Reconcile checkout attempts older than23h without blindly creating a duplicate. Make the repair auditable and account-scoped. Late cancellation/deletion webhooks must be acknowledged/idempotent rather than permanently retried as503.
4. Use authoritative subscription/invoice timestamps for the fixed72h payment-failure grace; late/reversed events cannot restart it. Document upgrade proration, period-end downgrade/cancellation and billing-portal settings.
5. Expand fixture state table: initial incomplete/failure, activation, renewal, upgrade, scheduled downgrade, cancellation/re-subscription, duplicate subscription, stale/duplicate/reversed events, unknown price, provider outage and provider-success/local-save failure.
6. Implement the task41 hostedtest-only phase barriers in owned code and a test proving production builds cannot activate them; include phase names in the integration receipt for task58.

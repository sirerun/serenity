## Required steps

1. Enter durable deleting state before provider work; block checkout and normal memory/session access. Use task47 provider closure before final irreversible data purge.
2. Append an integrity-checked, monotonically ordered deletion intent to the task41 independent journal before acknowledging deletion. Journal contains opaque IDs/timestamps/state only, no memory/email/token. Local SQLite alone is not an independent recovery source. Journal individual-brain and account deletion, never reuse a deleted opaque ID. This task owns the runtime production object-storage journal adapter and its fixture tests, not task52.
3. Order and resume billing closure, credential revocation, brain directory cleanup, session/token deletion and account anonymization. Journal append failure leaves deletion pending and restricted retry available; never acknowledge a durability guarantee not achieved.
4. Coordinate journal storage/IAM with task52 and infra integrator; use an explicit filesystem fake locally and stack-scoped durable object storage in production. Preserve all ordinary account/brain ownership checks.
5. Keep export a quota-independent operation; verify canonical facts and restorable bundle. Wire dashboard via integrator request, not concurrent edits to dashboard.go.
6. Implement the task41 hostedtest-only phase barriers in owned code and a test proving production builds cannot activate them; include phase names in the integration receipt for task58.

## Acceptance — all required

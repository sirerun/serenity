## 1. Context

Serenity is a native memory-provider option in Rakazo (elie222/rakazo PR 835, merged 2026-09-10 at `ef63e354`). The next milestone is a real hosted service: a person signs up at https://serenity.sire.run, receives a private brain, connects Rakazo over HTTPS, uses durable semantic memory, and can buy a paid monthly plan. The Apache-2.0 self-hosted product stays usable; hosting sells operation and capacity; private customer memory never becomes shared Ajent knowledge automatically.

Founder-confirmed inputs (David, 2026-09-11, recorded in the ADRs above):

- Identity: email magic link through Resend (ADR 015).
- Hosting: AWS us-west-2, the account already running `deploy/chat`, one ARM VM with EBS and S3 backups, fixed ceiling USD 60 per month (ADR 014).
- Plans: the proposed table (Free 0 / Builder 19 / Scale 49 USD) is ratified as plan configuration version 1 and is published on the pricing page with the app; the cost gate informs a later revision, it does not block publication (ADR 016).
- The launch-driving session reviews and merges PR stack #220-#225 and lands local commit `1dfecc8` through a PR; this is standing merge authority for that stack and commit only.

Non-negotiables from the directive: no weakening of isolation; nothing called production-ready before the acceptance matrix passes; no new brand or domain; no new payment account; no dependency on Zatiti Desktop, Sire billing, Ajent collective intelligence, a connector catalog or model training; no fleet-banned `ANTHROPIC_API_KEY` in the hosted path; no fake activity or sample data shown as real memory; test-mode billing and a release packet before any live activation; "launch-ready" is distinct from "launched".

Out of scope for this epic (record later work as a task with a reopening trigger, never build it here): enterprise SSO, team RBAC, multi-region, marketplace, general chat, connector catalog, public knowledge sharing, model training, annual billing, automatic overage charging, a new scheduling framework, desktop wrappers, mobile apps.

Generation defaults to OpenRouter (`OPENROUTER_API_KEY`).

No Dockerfile, k8s, systemd unit or hosted deployment target exists for the daemon. `deploy/chat` (CloudFormation, Lambda, DynamoDB, Secrets Manager, CloudWatch EMF, `deploy.py` change sets, `verify_live.py`) is the reusable deployment pattern.

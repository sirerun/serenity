# T23.48 / T23.52 journal and retention adapter discovery

Source reviewed: `main` at `6d62fe8e1a1766dbb85c05f861284cdc90a51280` (2026-10-01). This is a design receipt, not task acceptance or production qualification.

## Findings

T23.48 remains `planned` in `docs/launch/hosted-completion/tasks.json`. The main tree already has a substantial Go adapter in `internal/hosted/deletion/{config.go,store.go,journal.go}`. `NewAWSJournal` uses the AWS SDK v2 config default credential chain and constructs an S3 client; `S3ObjectStore` maps `PutIfAbsent` to conditional `PutObject`, `Get` and paginated `ListObjectVersions` to the SDK. Its local tests use a fake S3 API and the shared journal contract suite. The opt-in `TestS3Qualification` creates a disposable bucket and applies test IAM/bucket policy, but the follow-up receipt `docs/launch/evidence/T23.48-adapter-followup.json` explicitly says this was not run against current production IAM/bucket and leaves scoped credentials, task54 bucket/policy/role, lifecycle exclusion, and authoritative generation adoption open. Do not add a second journal API or infer production wiring from this code.

T23.52 also remains `planned`. `deploy/hosted/backup_completion.py` is a tested manifest-bound COMPLETE helper; `deploy/hosted/backup_retention.py` is a tested planner/executor behind a generic `Storage` Protocol. Their evidence files (`backup-completion-library-2026-10-01.json`, `backup-retention-library-2026-10-01.json`) explicitly mark them unwired. `deploy/hosted/backup.sh` still uploads the snapshot recursively with AWS CLI and then uploads a plain timestamp to `COMPLETE`; it does not call the completion helper or bind completion to the manifest hash. There is no retention S3 adapter, purge runner, purge unit, or timer in `deploy/hosted`. Bootstrap installs AWS CLI v2, while the hosted deploy tree has no pinned Python `boto3` dependency. The repository does use boto3 elsewhere (`deploy/chat`), but that does not make it an installed hosted-runtime dependency.

The frozen interfaces require journal completeness from the independent hash-chained journal, not the control DB (`docs/launch/hosted-completion/interfaces.md`, Decision 3); `COMPLETE` alone cannot authorize a snapshot. ADR 019 promises backup retention within 31 days and requires the purge job to verify expiry. T23.52 requires all-version/delete-marker and multipart inventory, exact-prefix/age checks, bounded pagination, denied-API failure, dry-run plan plus recorded destructive authority, and an hourly installed schedule. A fake adapter can test call translation and refusal paths but cannot establish bucket policy, IAM, actual inventory behavior, retention timing, or the disclosed deletion window.

## Smallest safe source-only adapter slice

The most useful bounded code slice is a new `deploy/hosted/backup_retention_s3.py` implementing the existing `backup_retention.Storage` Protocol with an injected boto3 S3 client. Keep it a translation layer only: pass through explicit bucket and `ExpectedBucketOwner`; map the planner's two pagination markers to `list_object_versions`, `list_multipart_uploads`, and `list_parts`; translate `Delete` results from `delete_objects`; map `abort_multipart` to `abort_multipart_upload`; convert only the SDK's exact `NoSuchUpload` service error from `list_parts` into `UploadNotFound`; propagate authorization, timeout, malformed-response, and all other errors. Do not load credentials, choose a region, construct a boto client, execute plans, or schedule purge from the adapter. The caller supplies a client and authoritative expected-owner value.

This slice needs an explicit dependency decision before packaging: boto3 is not declared or installed by the hosted bootstrap. The source/tests can be written against an injected client and exercised with a deterministic stub without credentials or network, but task54/bootstrap integration must pin and ship boto3 (or the coordinator must choose a different maintained client boundary). Do not reach into AWS CLI v2's private botocore bundle or shell out from the adapter as a hidden dependency workaround.

Suggested exclusive ownership for that source-only slice is `deploy/hosted/backup_retention_s3.py` plus a new `deploy/hosted/tests/test_backup_retention_s3.py`; coordinate `deploy/hosted/backup_retention.py` and task registry changes rather than editing them. Local controls should prove exact SDK operation/argument mapping including `ExpectedBucketOwner`, both continuation markers, all pages; only authoritative `NoSuchUpload` maps to empty upload parts; access denied/timeouts and malformed/truncated pagination propagate as errors; deleted versions and delete markers are both translated; no network/client construction occurs in import or adapter construction. Use fixture data and fake clients only.

Do not combine this with uploader/COMPLETE wiring or purge activation: those have separate ordering, ownership, and destructive-action contracts. A follow-on integration task should wire the tested completion helper only after the manifest is validated and immutable, upload artifacts first, upload the exact completion bytes last, and ensure download verifies both before restore. Purge requires a separately reviewed dry-run/apply invocation and pinned destructive-authority receipt; this adapter alone does not provide that.

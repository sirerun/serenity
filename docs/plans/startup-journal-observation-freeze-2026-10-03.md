## Frozen source shapes

New `internal/hosted/contracts/deletion_reader.go` contains exactly the proposal's `JournalObjectReader`, `JournalWriterUse`, `JournalPosition`, `JournalObservation` and `DeletionJournalReader` declarations. Existing `JournalObjectStore` need not be rewritten: it structurally implements the reader interface. `DeletionJournalReader` exposes only `Observe(context.Context) (JournalObservation, error)`. A concrete read-only wrapper must not expose append/seal/conditional-write methods or a writable store getter.

Deletion adds `NewJournalReader(reader contracts.JournalObjectReader, position contracts.JournalPosition) (*ReadOnlyJournal, error)` and `NewJournalAt(store contracts.JournalObjectStore, writerID string, position contracts.JournalPosition, now func() time.Time) (*Journal, error)`. Constructors validate the structural position and nil capabilities. The observer verifies complete canonical history from generation1 through the bound positive active generation, including seals, under the caller's externally established stable namespace reservation. It does not authenticate provider identity or claim snapshot consistency by itself. Position issuance/allocation IDs are trusted authority inputs; the later factory reconciles them and every writer use against durable issuance records before activation.

A valid position has positive generation within the existing ten-digit key domain. Generation1 requires nonblank genesis issuance, zero predecessor seal, no successor allocation; generation>1 requires nonblank successor allocation, no genesis issuance, exact positive G-1 predecessor seal. A nonzero last active object has the same active generation, positive sequence, lowercase SHA256 hash and must be the verified unsealed head. Empty active generations retain zero LastObjectInGeneration and require the exact prior seal for G>1. Never infer active generation from last visible watermark or synthesize generation0.

Observation verifies all preceding generations are sealed and no object follows a seal. It verifies the bound predecessor seal and exact active head, refusing stale positions, gaps, rewrites, malformed objects, conflicting writer generations and cancellation. Read includes all entry records from generation1; To is the last verified object (previous seal for an empty successor, zero for empty genesis), with existing Sealed semantics. WriterUses includes each unique writer in first-object-use order across entries AND seals; repeated same-generation use collapses, cross-generation reuse is rejected only by this stricter observation/new constructor path. Legacy ReadThrough remains compatible.

HistorySHA256 uses SHA256 over the byte concatenation, in verified key order, of each object's uint64 big-endian byte length followed by its exact canonical stored bytes. Empty history is SHA256 of empty bytes. This unambiguous domain includes entries and seals; key coordinates are already encoded/validated inside each object. Tests independently compute expected digests, including a seal-only writer and rewritten-history rejection.

NewJournalAt initializes its append cursor from the exact bound position and never uses lazy loadHead to advance past it. Before its first append or seal it verifies full reserved history/position through the reader-only path, and conditionally creates exactly the next reserved key with the reserved predecessor. A changed/taken key, stale head, seal, changed predecessor or later object fails closed; no adopting another writer's cursor. Existing ambiguous byte-identical PUT retry semantics remain. The externally enforced exclusive epoch is still necessary to prevent a race between observation and write; this component never asserts that IAM revocation has occurred.

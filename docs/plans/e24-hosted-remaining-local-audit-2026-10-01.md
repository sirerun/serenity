## Concrete local gaps

- **Hosted service and operator commands are deliberately unavailable at this source pin.** `service.New` and `service.Assemble` return `ErrStartupUnavailable`; `cli/hosted.go` does the same for `hosted serve`, `hosted backup`, and `hosted restore`. `AssembleWithDependencies` correctly requires an injected journal, build identity, and `RecoveryAdmission`, then requires both the admitted-cut and full-history reads to terminate at the same verified seal before replay. No production coordinator currently constructs those dependencies or proves prior-writer fencing plus active-generation adoption. `deletion.NewAWSJournal` is an adapter using the default AWS credential chain and a configured generation; that constructor alone is not generation-adoption authority. This fail-closed behavior is intentional. Do not restore a default filesystem journal, infer a generation from visible sequence numbers, or add a dev exemption to claim readiness.
- **Restore is not an executable plan/apply capability yet.** `internal/hosted/recovery` persists and validates a bounded immutable plan; the plan hash does not authenticate approval, current provider truth, a complete journal boundary, or writer adoption. `internal/cli/hosted_recovery.go` is absent. The additive `RecoveryBillingObserver` interface is present in contracts, but billing has no implementation of `ObserveRestorePending`; the separate observer-contract lane in the T23.50 evidence record must finish first. Existing `BillingReconciler` behavior must remain unchanged for frozen accounts.
- **The installed backup script path is not the new verified upload/retention pipeline.** `deploy/hosted/backup.sh` calls `serenity hosted backup`, then recursively runs `aws s3 cp` and uploads a timestamp text file named `COMPLETE`. At current source, the CLI backup command fails closed before producing that snapshot. The deployed host's binary was explicitly not replaced in the E24 evidence, so this source observation does not establish that its current timer run fails. `backup_completion.py`, `backup_retention.py`, and `backup_retention_awscli.py` are local helpers; the latter two describe themselves as unwired. There is no `purge.py` or purge service/timer in the tree. The only installed unit pair is the daily backup service/timer. Consequently no source-level end-to-end path yet binds uploaded bytes to the manifest-v2 completion hash and executes a bounded all-version purge. No 31-day result may be claimed from the current S3 lifecycle template or these helpers.
- **Physical storage admission remains blocked, despite operation-ledger progress.** The T23.44 receipt is `PARTIAL`; its missing requirement is still an allocation-based maximum mutation-stage measurement plus an OS-enforced staging limit. `interfaces.md` and `contracts/storage.go` state that `StageMeter` is cooperative and does not enforce filesystem growth. A measured serialized payload or a fake `StageMeter` test is not a physical quota bound.
- **The hosted SEC-H05 Git migration is incomplete.** Non-test direct Git execution remains in `internal/hosted/pool/pool.go`, `internal/hosted/provision/canonical.go`, and `internal/hosted/gateway/lifecycle.go`. Their task contracts already assign migration respectively to T23.45, T23.46 and T23.48. The current `internal/gitrun` drift test scans only seven local-product roots and says it is not yet module-wide. The T24.30 acceptance calls for a whole-module parser check, so evaluate all non-test Go sites before implementing it: current `evals/` sources also directly call Git, even though several only read the trusted source checkout. Migrate or get an explicit contract ruling for each such site; do not silently weaken the frozen scanner scope.
- **T24.28 has no executable ACL implementation in the current tree.** `internal/secrets` delegates to `github.com/zalando/go-keyring` v0.2.8, whose macOS backend invokes `/usr/bin/security`; `internal/secrets/secrets_test.go` mocks the keyring in `TestMain`, so it cannot verify a Security.framework ACL or whether a read prompts. The prior ACL implementation was reverted specifically because silent Security.framework reads were not established. The CI cross-build also requires `CGO_ENABLED=0` for Darwin arm64. A native bridge therefore needs an explicit compatibility design for the shipping no-CGO binary; a CLI fallback that prompts would not meet the task.

# Private positive-only operator resolution development seam

Coordinator freeze for the next source slice, based on main338 and read-only Ledger.Lookup. This adds no automatic pending_review exit and changes no frozen contracts/OperationLedger interface. It does not establish a production authenticator, immutable case store, private socket listener or operator factory.

Service-only optional dependency: LifecycleDependencies.OperatorReviewAdmission, assigned to Service's private field. Required journal startup validation stays unchanged; typed nil counts as absent for this route. The interface is Authorize(ctx context.Context, request *http.Request, operationID, reviewRef string) (ApprovedOperatorReview, error). ApprovedOperatorReview contains OperationID, ReviewRef, OperatorID, Outcome contracts.OperationPhase, ExpectedCanonicalRef and ApprovedAt time.Time. Trusted admission authenticates a human operator and loads a durable immutable approved case before any ledger lookup or runtime fence. It must verify case integrity, unique reference binding and revocation policy. Never derive operator identity from request JSON or a caller-supplied role.

Only AdminHandler receives POST /operations/resolve. Public Service.Handler has no route. Missing admission returns503. Request is at most4096 bytes and contains exactly operation_id and review_ref strings. Token-level strict parsing rejects duplicate keys, unknown fields, case aliases, non-string values and trailing data; DisallowUnknownFields alone is insufficient. Opaque identifiers/references are bounded and contain no whitespace/control characters. Body has no outcome, actor or canonical proof fields.

Authenticate first, then verify returned case binds exact requested ID/ref, nonempty opaque operator identity, nonzero approval time, nonempty bounded canonical ref and fixed committed outcome. Invalid or unauthorized case returns a fixed denial before lookup. Case authorization error text is never returned or logged. Context cancellation leaves accounting unchanged.

Lookup supplies the brain/account and original counters. Reserved/released/other mismatched phases refuse. Exact already-committed OperatorReview evidence with the same reviewRef may replay after authorizing the same immutable case, with no charge change; different evidence/ref conflicts. For pending_review, acquire the Gateway.OperationReconciler fence, defer release, reread under that fence, recheck phase/idempotency, then Check. Only Landed with Ref equal to case.ExpectedCanonicalRef permits ResolvePendingReview(committed, EvidenceOperatorReview{Ref: unchanged reviewRef}), while retaining the fence through the transition. Unknown, Absent, errors, cold/inactive/missing brain, canceled context or changed row never release quota. No released action exists. The approved immutable case already durably binds the expected exact canonical proof, avoiding a separate mutable attachment stage.

All successful responses are204 with no customer payload, client key, fingerprint, counters or proof refs. Refusals use fixed errors. Error/status distinctions may exist only after trusted authorization. Private transport/provider adapters remain absent; the optional test fixture is not a production authenticator. Tests must prove unauthenticated/no-adapter denial before lookup/fence, strict parser refusals, public route absence, case/proof mismatch, actual landed original-period settlement exactly once, unknown/cold/inactive capacity holding, canceled paths, and fence retained through proof and ledger transition. Use deterministic barriers, not synchronization sleeps.

Source ownership: assigned worker only internal/hosted/service/** and its own new review/implementation receipt. Coordinator owns this contract, roadmap and integration. Concrete Ledger.Lookup is already independently reviewed and remains read-only; gateway/pool contracts are read-only for this slice. No migration, provider call, deployment, CLI activation or frozen state-machine amendment.

## Trust chain and broker

Linux root-owned broker daemon listens on a freshly created Unix socket under root-controlled directory, exact configured service UID only. Linux SO_PEERCRED supplies PID/UID/GID, never headers or body. Read `/proc/PID/stat` start time, open `/proc/PID/exe`, hash open descriptor, re-read start time, and reject any mismatch; hold a Linux pidfd for the exact peer process lifetime; unsupported pidfd or failed acquisition rejects production admission. Immediately before each gateway mutation poll the held pidfd for exit and recheck the held proc-directory starttime/executable identity and unit tuple. A reused numeric PID cannot replace the held process capability. Reject executable containing `(deleted)` and reject executable path/config whose parent or file is service-writable. Broker queries the root-controlled configured systemd unit over the system manager API; require ActiveState=active, MainPID exactly equal to SO_PEERCRED PID, and kernel /proc/PID/cgroup membership exactly equal to the unit ControlGroup. Query before and after executable hash/starttime measurement; any unit restart, inactive state, unavailable manager or changed tuple rejects admission. An arbitrary same-UID process running the approved executable is rejected. Socket responses and operations are bound to connection and kernel peer; no transferable bearer credentials are emitted to service. Recheck PID lifetime, exact unit MainPID/ControlGroup and executable file identity before every state-changing request; PID reuse, peer disconnect and daemon shutdown revoke the durable session. A crashed daemon leaves expiry/fence enforcement to gateway, never authority to local process memory.

Broker pinned config contains exact AWS region/API Gateway invoke ARN/HTTPS origin, allowed UID, release manifest pin/build and executable SHA256, deployment identity, and explicit credential source. No service-selected host/build/UID claims. Broker alone signs requests with scoped SigV4 execute-api credentials acquired from explicitly configured IMDSv2 instance profile (root process network namespace; service metadata access denied). No config.LoadDefaultConfig ambient provider, env credentials, default profile or endpoint override fallback. Broker endpoint must be a configured canonical HTTPS API Gateway host; no redirect, arbitrary URL, proxy environment or HTTP fallback. Remote API authorizes exact requestContext identity from AWS_IAM gateway and maps authenticated role/session identity to approved deployment; client-supplied identity fields cannot substitute for authenticated transport identity. An AWS instance identity document is supplemental and never a bearer authorizer.

Gateway authenticates broker transport identity and checks broker measured executable against owner-pinned release digest/build in durable approved deployment state. Broker role can invoke only scoped runtime API methods, cannot write DynamoDB, call KMS signing or change release policy. Authority Lambda role owns constrained DynamoDB operations. Recovery operator uses separately admitted role/API and cannot be impersonated by runtime request bodies. Broker is security boundary and root compromise is outside service-UID threat model, explicitly recorded.

## Cross-lane API to freeze

Use existing contracts.JournalPosition, JournalObservation, DeletionWatermark and immutable canonical JournalObject bytes.

- BeginStartup(ctx, authenticated broker identity, verified peer measurement, operationID) -> Session {ID, Epoch, WriterID, BuildSHA, Position, ExpiresAt}. Identity and measurement are constructed only inside broker transport; service only asks to start. DynamoDB conditional transaction requires approved release/deployment, no active incompatible session, and exact expected head. It persists admission operation/result for ambiguous retry.
- Observe(ctx, session) -> contracts.JournalObservation. Uses immutable reads restricted through session Position and verifies exact namespace/hash-chain/writer issuance history. Admission is rejected if expiry/revocation/head epoch changed. Empty genesis requires durable genesis issuance, never absence alone.
- CommitObject(ctx, session, expectedHead, key, bytes) -> created bool. Single DynamoDB transaction requires current active epoch/session/lease and expected head; checks bytes' coordinates, predecessor, WriterID, exact allowed kind; immutable object put and authority head advance happen atomically. Byte-identical retry returns committed result only after confirmed operation/head lookup. Stale/fenced session never reaches generic create. Runtime can append entry but cannot seal/allocate successor.
- Current(ctx, session) -> typed current position and active/revoked state (strongly consistent). Readiness fails on unavailable/expired/revoked/mismatched session. No cached affirmative readiness beyond request.
- BackupCut(ctx, session, operationID) -> Cut {ID, Position, Epoch}. Authority captures durable head under valid active session. Reader exposes immutable journal exactly through cut, including prior sealed generations. Complete verification returns unforgeable package-private proof around contracts.JournalObservation. Cut does not reserve future write capability and does not stop appends; later writes cannot alter immutable prefix. Prefix listing is implemented by sequence bounds, not filtering arbitrary untrusted listings.
- Revoke(ctx, session, operationID) -> durable terminal result. Idempotent exact operation; gateway rejects future append immediately after commit. Session expiry does not grant another writer without authority CAS/reconciliation.

Session and cut serialized claims alone are not admission. Go public constructors validate server/authenticated response plus live authority; no exported bool-returning arbitrary production injection. Narrow fakes belong only in _test.go. Service receives concrete admitted runtime wrapper from production factory.

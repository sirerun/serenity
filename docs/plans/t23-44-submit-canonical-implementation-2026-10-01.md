`Queue.SubmitCanonical(ctx, job)` serializes a source mutation with the queue's exclusive commit fence without flushing Git. The drain acquires the shared commit guard before `runMu`, executes Render and touched-path tracking, releases the shared guard, executes optional ordered `AfterGuard` work while retaining `runMu`, then releases `runMu` before the hook. The callback lets index cleanup run without holding the checker-excluding fence, while retaining the existing queue and Flush ordering. Callbacks must not call back into the same queue. `SubmitAndFlush` retains its existing inline publication behavior; ordinary `Submit` remains available for provider/index-only work.

The new guarded path is used by non-inline `MemoryFact.RememberContext`, `MemoryFact.Forget`, `MemoryFact.CancelRemoteOperationContext`, and `SourceTombstone.TombstoneContext`. Existing legacy wrappers use `context.Background`; context variants can cancel while waiting before Render. Forget and tombstone run source-store changes and history rewriting under the shared fence; index purging is ordered after the fence releases. A post-callback error is joined with the Render/flush result and reported to the caller. Because source deletion may already be durable when index cleanup fails, callers receive an error that can describe a partial operation; retries remain the recovery path.

# T23.49/T23.50 verified snapshot inspection development contract

Coordinator integration handshake v1, based on merged main340 6d62fe8 and design b8aba733. A new inspection API is approved only as a local prerequisite. Frozen contracts.RecoveryPlanner/RecoveryApplier/BillingReconciler and existing recovery plan storage remain unchanged. Do not issue eligible plans, activate accounts, call providers or wire a CLI/factory.

## Interface and truthful result

Add backup.InspectSnapshot(ctx context.Context, snapshot string, options InspectionOptions) (SnapshotInspection,error). Options require ScratchRoot (explicit absolute canonical owner-private directory), ExpectedManifestSHA256 (exact64 lowercase hex caller-supplied approved-byte binding), MaxDeclaredBytes (positive int64 <=1TiB), MaxAccounts and MaxBrains (positive ints <=10000). No defaults, temporary-directory fallback or inferred approved digest. Context is first, nonnil and checked before I/O and across copying/SQLite/Git operations. Inputs and results are development metadata, not authenticated authority.

Result fields: ManifestSHA256, Source (contracts.SourceIdentity/actual existing ManifestV2.Source type), JournalWatermark, sorted Accounts of {ID,Status}, sorted Brains retaining manifest ID/empty/head metadata, VerifiedArtifactCount and DeclaredArtifactBytes. Use an accurately named exported result type for each inventory; no emails, provider customer IDs, credentials or fact contents. Keep source BuildSHA separate from exact raw manifest digest. Return zero result on any failure. Account statuses are original snapshot statuses, not eligibility; do not filter deleted/deleting or label any account eligible. Enforce opaque bounded identifiers, allowed schema statuses and configured inventory ceilings before unbounded materialization.

The exact manifest bytes read once are hashed before conversion. Compare ExpectedManifestSHA256 before creating scratch or copying artifacts. Manifest parser/canonical rules, legacy refusal and current schema support remain the existing ones. Inspect the same opened os.Root, not separately reopened untrusted paths. A changed source artifact may only produce the exact originally approved bytes or a refusal.

## Shared verifier, no publication

Reuse/extract the backup package's real validators: strict manifest parser; single-pass artifact length/SHA verification; actual control-DB integrity/schema; manifest-vs-ready-brain inventory; bundle integrity and exact restored local heads. No second parser or manifest-only claim of verified snapshot.

A narrow shared stage/verifier extraction may serve Restore and Inspect, but keep restore's migrations, credential/session revocation, freezing, writer-identity configuration and atomic destination publication separate. Inspect must not call store.Open, migrate/freeze the copied DB, change source data or publish any restore destination. Read verified control bytes through mode=ro, immutable=1, query_only SQLite with URI-escaped paths and context-aware queries. Reuse inventory validation through a narrow private SQL query seam rather than requiring a mutable store. Close errors cannot acknowledge success. No injected production stub, faked journal or provider authority.

Scratch is a fresh0700 child under options.ScratchRoot, created only after privatefs.ValidateDirectory. Snapshot directory likewise must be canonical owner-private with trusted ancestors and ownership enforcement. This slice depends on PR341's privatefs merge; implementation starts only after that prerequisite is merged. Copies are0600; subsequent Git/DB reads use only verified private copies. Cleanup removes only exact scratch created by this invocation on every success/error path, never caller files. No environment HOME reuse or internal-disk fallback.

Declared bytes sum must be overflow-checked and bounded before copy. Bound each copy to its expected length plus one detection byte (without int64 overflow); do not let io.Copy consume an arbitrarily growing source. These are logical declared/copy limits only. Git clone expansion, SQLite/Git metadata and physical allocation are not proved bounded by MaxDeclaredBytes. An OS quota-limited scratch filesystem and measured allocation remain capacity/activation prerequisites; do not claim hard disk limits or production hostile-input capacity qualification here.

Strengthen shared source-file opens for manifest/artifacts to no-follow, nonblocking regular-file opens/fstat, with context and size/read bounds. Reject FIFOs/devices/symlinks and replacement/growth instead of blocking or following them. Preserve os.Root confinement. Platform helpers may be added inside backup for Darwin/Linux; unsupported inspector behavior fails closed rather than inventing safety. This is a coordinator-approved backup-owned hardening, not authority to edit gitrun/store or other packages.

No RecoveryPlan, Apply, Seal, successor adoption, provider call, deployment, spend, purge or activation is supplied.

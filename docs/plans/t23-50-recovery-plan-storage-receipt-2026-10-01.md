# T23.50 immutable recovery-plan storage receipt

Source base: main337 `06e22d019dccd04963f6309c13e0b45f441c7e8a`. Final candidate source: `4a4d52d33e1ba6dae38c5a74957faa030c1151eb` (includes `35f4b85fe8b4f1a3b781d6b194cfec6e2fc66eb0`).

This bounded prerequisite adds `internal/hosted/recovery` plan persistence only. `CreatePlan(ctx, dir, input)` canonicalizes a sorted, unique account scope and persists an immutable, hash-named JSON artifact. Its SHA-256 covers canonical payload fields excluding the hash: format version, supplied exact manifest-byte SHA-256, deletion-journal watermark, fence generation, UTC provider observation time, and account IDs. `LoadPlan(ctx, dir, expectedHash)` reloads only that approved hash and validates the hash, canonical bytes, field relationships, and account scope. The decoder bounds file/account count and rejects duplicate keys, unknown or case-aliased fields, malformed nested objects, and trailing JSON. Plan directories must be absolute, private mode 0700, current-user owned, non-symlink directories; every ancestor is checked for trusted ownership, unsafe writable mode, and filesystem ownership enforcement. Plan files are opened without following symlinks or blocking on special files, then required to be private regular files. Publication uses a synced same-directory temporary file, atomic no-overwrite hard link, and directory sync. Existing byte-identical plans are idempotent; corrupt or conflicting paths are never replaced. Platforms without the required safe filesystem support fail closed.

Verification on the isolated main337 clone: `go test -race ./internal/hosted/recovery -count=1` passed (`ok`, 1.443s) on final source `4a4d52d`, with fixtures on the owner-enabled APFS validation mount and external Go caches/temp. The run set `SERENITY_RECOVERY_UNOWNED_TEST_PATH=/Volumes/BuildOffload` and exercised the Darwin test against the ownership-disabled build volume; the test confirms that such a filesystem is refused. The single-package load guard was satisfied; no shared build lease was needed. Tests cover create/load/hash stability, sorted scope, idempotent create, wrong approved hash and modified payload, duplicate/unknown/case-alias/trailing JSON, corrupt-file no-overwrite, symlink target and plan-directory refusal, cancellation before I/O, malformed digest/scope/time/generation, and FIFO refusal.

Two runtime mutation controls produced genuine RED results before restoring the committed implementation. The higher-ancestor control against the pre-fix source returned `CreatePlan accepted writable higher ancestor: <nil>`; the corrected path walk validates ownership and write/sticky safety for every ancestor and checks filesystem ownership enforcement at each level. The FIFO control first used an incorrect fixture filename and falsely passed; that probe was discarded. After correcting it to the exact hash-derived artifact name, the pre-fix blocking opener failed with `LoadPlan blocked opening a FIFO past its context deadline` after 500 ms. The fixed opener uses `O_NONBLOCK`, after which the full recovery-package race test passed. The FIFO control leaves a blocked goroutine only in the intentionally failing old-source test process, which exits immediately after the test failure; the corrected implementation returns promptly.

This package does not read a snapshot, compute or authenticate the supplied snapshot digest, obtain provider truth, establish operator approval, seal or adopt a journal generation, revoke old credentials, plan, apply, activate accounts, or register a CLI command. `SnapshotSHA256` is deliberately distinct from build identity; the future planner must derive it from the exact manifest-v2 bytes and must not silently coerce it into the frozen `contracts.RecoveryPlan.SourceSnapshot` field. The payload hash detects artifact changes but is not a signature or proof of truth. Existing `LifecycleDependencies.RecoveryAdmission` and provider-free filesystem-journal test fakes remain unchanged and do not authorize production startup. T23.50 remains partial pending authenticated snapshot/provider inputs, explicit old-writer stop and credential/session revocation, durable seal plus successor-adoption evidence, service/CLI integration, and operator-controlled qualification.

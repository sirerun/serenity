## Storage handshake and identity

The current helper exposes `RemoteObject(key, version_id, delete_marker)` and `list_prefix`, but its read calls accept only a key and snapshot download reads control objects before listing. A key-only read cannot prove which version was read if a key changes between inventory and GET. Do not use a hidden per-prefix cache or depend on call order/adapter reuse.

Make only this narrow additive API change in `backup_publish.py` when implementing the transport: `read_bytes(key, *, version_id, max_bytes)` and `read_to(key, destination, *, version_id, max_bytes, chunk_bytes)`. Both must use the supplied opaque version ID in the exact GET. Change downloader order so it obtains and validates the full bounded version inventory first, selects exactly one latest non-delete-marker version for each required control/artifact key, and passes that version ID to every read. The downloader must retain the selected identity while checking manifest membership and hashes; it must not switch to a newer version mid-run. A missing, duplicate, non-latest, null-ID, or delete-marker selected object fails closed. This is a limited helper handshake, not an installed-interface or caller-wiring change.

Writes continue through the existing `put_if_absent(key, source, *, length, sha256)` helper contract. Treat `ObjectExists` as failure even where remote bytes match; only the helper's existing exact final-COMPLETE reconciliation may qualify a lost final response after full readback of exact bytes and digest.

## Complete version inventory

For each exact snapshot prefix, issue `s3api list-object-versions` with expected owner, `encoding-type=url`, `max-keys=1000`, no delimiter, and manual pagination (`--no-paginate`). On continuation send both markers exactly as returned after strict one-time URL decoding/validation. Require valid bounded JSON, an explicit boolean `IsTruncated`, arrays of version/delete-marker entries, and advancing paired markers whenever truncated. Reject malformed pages, unknown/truncated state, repeated/no-progress markers, common-prefix entries, duplicate `(key, versionId)` identities, invalid percent escapes or UTF-8, prefix escape, empty/null version IDs, and response/page/total-object bounds violations. Count every object version and every delete marker toward the configured object ceiling; never collapse by key. Return the complete inventory or fail—never a partial result.

Only a latest ordinary version can be selected for a read. Reject inventories that cannot prove exactly one latest ordinary version for a required key. Existing historical versions are allowed only where the publisher's no-overwrite policy permits them; delete markers and any previously occupied destination key block publication. The implementation must not infer absence from a current-object listing.

## Bounded, streaming upload

Before any write request, spool the caller's source into a newly created private regular file in a caller-provided private scratch directory. Create exclusively with mode 0600; reject symlink/non-directory scratch, unexpected ownership/permissions, destination collision, changed source identity/metadata, short/extra data, declared-length mismatch, hash mismatch, disk-full, or failed cleanup. Hash and count incrementally; memory use is bounded by a fixed chunk independent of snapshot size. Enforce the declared length and configured total snapshot/object ceiling during the copy, not afterward. Do not use runner stdin as an object body.

For each object, use `put-object --if-none-match '*' --expected-bucket-owner ... --body <private-file>` when size is within the single-PUT service limit. For larger objects use `create-multipart-upload`, bounded file-backed `upload-part` calls, and `complete-multipart-upload --if-none-match '*' --expected-bucket-owner ...`. Choose a configurable part size in the supported range that stays within 10,000 parts for the 500 GB ceiling; all nonfinal parts meet the S3 minimum. Bound each child request, JSON/stdout/stderr, part count, part manifest, aggregate retries (none for ambiguous writes), elapsed time, and scratch use. Preserve exact returned ETags in part order; never equate multipart ETag with SHA-256.

On a multipart failure, abort only the exact upload ID created by this operation. If abort or scratch cleanup cannot be established, report failure and produce no qualified receipt/COMPLETE. Do not retry uncertain PutObject/CompleteMultipartUpload outcomes blindly. Map definite 412 to occupied destination. A 409, timeout, malformed response, or lost connection is ambiguous and cannot be reported as successful; final COMPLETE may be reconciled only through the helper's exact full-byte/hash readback rule. Require a lifecycle control to expire abandoned incomplete multipart uploads; version inventory cannot enumerate those uploads.

## No-overwrite and versioning semantics

S3 `If-None-Match: *` is a current-version condition. In an enabled versioned bucket, it can succeed when the current version is a delete marker. It is not an all-history-absent primitive. Do not document or test it as one.

The operational contract for safe publication therefore requires all of the following together: a general-purpose bucket with versioning continuously Enabled (never Suspended); preflight complete version inventory that blocks any destination key with any version or delete marker; conditional headers on every PutObject and multipart CompleteMultipartUpload; policy enforcement of those conditions; and an exclusive publisher-writer gate plus IAM/bucket controls that deny runtime `DeleteObject`, `DeleteObjectVersion`, versioning suspension, and concurrent lifecycle/admin mutations that could add a delete marker or remove a current version during publication. Two cooperating publisher calls race safely on an absent current key because the conditional final write admits one winner. The deployment owner must prove the exclusive-writer and mutation controls close the gap between inventory and conditional write. If it cannot, the implementation may claim only conditional-current-version protection and must remain unqualified for all-history no-overwrite. A preflight inventory by itself does not close that race.

A pre-existing delete marker, suspended versioning, null version ID, wrong owner, directory bucket, or policy that does not enforce conditional writes is a hard refusal. Do not attempt to repair these states automatically.

## Bounded, version-pinned downloads

Use `get-object --version-id <selected-id> --expected-bucket-owner <owner> <key> <private-outfile>` to a unique private 0600 file. Do not ask the CLI to buffer the object in memory. Validate command result, response metadata/identity where available, regular-file/no-follow identity, size against expected and configured per-object/total bounds, and stable file identity/size/mtime before and after streaming. Read incrementally and write to the caller destination in chunks no larger than `chunk_bytes`; handle short destination writes explicitly. Reject wrong version, truncation, growth, mutation, oversized chunks, output overflow, timeout, and cleanup failure. Publisher digest verification remains mandatory. The returned bytes are staged data only: this adapter grants no activation/install authority.

At every operation maintain bounded JSON and stderr/stdout bytes, request count, page count, part count, wall-clock deadline, file descriptors, resident memory, and scratch quota. Bounds must be explicit config values with safe hard ceilings and validated before child creation. Clean only files and upload IDs created by this invocation; never recursively clean caller-owned paths.

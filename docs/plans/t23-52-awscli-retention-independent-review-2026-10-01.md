Three runtime blockers need correction before integration:

1. At `backup_retention_awscli.py:409`, the exception tuple names `selectors.SelectorError`, which is absent from Python 3.14.6. When the selector pump raises an `OSError`, evaluating that exception tuple raises `AttributeError`, masking the fixed `AdapterError` promised by the adapter. I reproduced this using a mocked selector and paused fake subprocess; no AWS process or host signal was involved. Evidence: `/Volumes/BuildOffload/tmp/retention-cli-selector-leap-repro.log`, SHA-256 `997f69dd8904e6b116c860ad729280e400fcd61957a76ff62dbb853888773b4c`.

2. `_snapshot_key` at `backup_retention_awscli.py:55` validates calendar values with `time.strptime`. On this runtime, that parser accepts seconds `60` and `61`; the existing retention planner rejects both as malformed. Thus the adapter admits keys/markers the planner considers invalid. I reproduced both forms against the adapter and planner. They should use the same strict timestamp validation as the planner. Evidence is in the selector/leap repro above.

3. `_run` waits/reaps the child before its `finally` block calls `_signal_group`; `_signal_group` then signals the numeric process-group ID. A reaped PID/PGID can be reused before those signals, so cleanup can target an unrelated process group. A deterministic probe replaced `os.killpg` with a recorder and showed both signals occurring after `process.returncode` became `0`; it sent no real signal. Keep the child leader unreaped while signaling its owned group, using `waitid(WNOWAIT)` where supported, then reap exactly once. Do not call `poll`/`wait` before group cleanup. Missing capability or `ECHILD` should fail closed rather than signal an unanchored numeric group. Evidence: `/Volumes/BuildOffload/tmp/retention-cli-lifecycle-order-repro.log`, SHA-256 `a2270d42bdaa5aefc9016546e0549841ddcc900801292d480d1f10b96571302c`.

One additional contract mismatch: `_text` rejects C0 and DEL controls but accepts Unicode C1 controls U+0085 and U+009F. The frozen contract says strings contain no control characters. Direct `_identifier` calls returned those values unchanged. Validate all Unicode `Cc` characters (without normalizing otherwise opaque identifiers) and add coverage. This observation was reproduced directly in Python; it did not call a provider.

The review did not assess actual AWS CLI compatibility against a live service, credential identity or IAM permissions, deployment, retention scheduling, or purge authority. The adapter remains an unwired library candidate; passing local fake tests cannot establish the separate live 31-day qualification or completion/manifest authority gates.

## Trust and revocation boundary

Implement operatorreview.Admission structurally satisfying Service.OperatorReviewAdmission through its existing Authorize method. TrustedKeySource.Lookup(ctx, keyID) returns a fresh currently authorized key record: PublicKey (Ed25519), OperatorID, NotBefore, NotAfter, Revoked. Constructor requires an explicitly injected source; missing/typed-nil source is refused. The source contract requires authenticated current authority, unique mapping and uncached revocation; no production source is supplied in this slice. A valid signature proves a decision attributed to that configured trusted key; it does not prove a human actually inspected the case. Human enrollment, external immutable issuance/retention and current trust-source provenance remain activation gates.

Successful Authorize is the development admission linearization point. Revocation denies subsequent admissions, including retries; an already admitted request may finish while waiting for the canonical fence. This policy must be explicit in the receipt and deterministic tests. It is not a claim of immediate cancellation of every uncommitted approval. Production policy approval remains open; do not activate this verifier with actual keys/cases. No Service interface expansion or second provider lookup under the runtime fence.

Policy has mandatory ExpectedPeerUID, MaxCaseAge, MaxCaseLifetime and Now func() time.Time; no default trust, expiry or clock. Durations must be positive. Constructor requires ExpectedPeerUID equal to service effective UID and a valid private directory. Every Authorize requires a live context and request, with authenticated matching UID in both context and request context, before any file or trust-source read. Headers, body identity fields and direct public contexts cannot authenticate.

## Case bytes and validation

ReviewRef is exactly sha256: followed by64 lowercase hexadecimal characters, over the entire canonical signed envelope bytes including signature, with no self-referential review_ref. Filename is that digest plus .json; no caller path components accepted. Maximum case8192 bytes. Signed flat envelope contains exactly version (integer1), key_id, operator_id, operation_id, outcome (committed only), expected_canonical_ref, approved_at, expires_at, signature. Exact canonical field order is frozen by a documented typed struct; JSON marshal bytes with no newline. Duplicate keys, aliases, unknown fields, trailing documents, nested/wrong types, invalid UTF-8 and oversize all refuse. Signature uses canonical padded standard base64 for exactly64 bytes.

Signature message is bytes serenity.operator-review.v1 followed by one NUL byte, then canonical JSON of the same fields excluding signature, using the documented typed payload field order. KeyID is ed25519-sha256: plus lowercase SHA256 over the32-byte raw public key. Trusted record OperatorID must equal signed operator_id; all identity comes from trusted mapping. Bounded ASCII opaque IDs (1..256 bytes, no whitespace/control); exact current canonical proof syntax fact: plus64 lowercase hex. This source supports positive remembered-fact proofs only; it must not invent another proof format.

approved_at/expires_at and trusted validity dates are canonical UTC RFC3339Nano. Require key NotBefore<=approved_at<=now<key.NotAfter, now<expires_at, expires_at>approved_at, age<=MaxCaseAge, lifetime<=MaxCaseLifetime and not revoked. No future clock skew accepted. Source errors, invalid key size/digest/mapping and bad signature deny. Return only existing ApprovedOperatorReview fields, exact operation/ref and fixed committed outcome. No mutation or raw upstream error exposed by the Service handler. Explicit context checks bracket file read, key lookup and return.

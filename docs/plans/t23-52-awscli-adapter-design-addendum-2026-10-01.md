# T23.52 AWS CLI storage adapter design addendum

This addendum supersedes the boto3 adapter recommendation in `t23-48-52-journal-retention-adapter-discovery-2026-10-01.md`. The selected local substrate is the already-installed AWS CLI v2. This remains an unwired design; no AWS command was run.

## Proposed boundary

Add `deploy/hosted/backup_retention_awscli.py` implementing the existing `backup_retention.Storage` protocol, with a separate `deploy/hosted/tests/test_backup_retention_awscli.py`. The adapter must be inert at import and construction: it receives an explicit AWS CLI executable path, region, expected account owner, bucket, timeout/output ceilings and private scratch root. It never searches PATH for a different executable, loads credentials itself, chooses a bucket/owner/region, starts a purge, or schedules work. Protocol calls that pass a bucket or expected owner different from the configured values fail before subprocess creation. Listing/deleting/aborting is restricted to the fixed `snapshots/` namespace and validated keys/upload IDs.

Use `subprocess.Popen` with a fixed argument vector and `shell=False`; never interpolate values into a shell string. Every call pins `--region <region> --no-cli-pager --no-paginate --output json --cli-error-format json`. Calls pass `--expected-bucket-owner <account-id>` wherever the command supports it. `--no-paginate` is required because the planner, not the CLI, owns bounded pagination and continuation-marker validation. The CLI reference documents the pagination controls and structured JSON errors ([AWS CLI pagination](https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-pagination.html), [structured errors](https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-error-format.html)).

Map protocol operations to the documented `s3api` request shapes:

- `list_object_versions`: `list-object-versions --bucket --expected-bucket-owner --prefix snapshots/ --max-keys 1000`, with `--key-marker` and `--version-id-marker` only when supplied. Preserve `Versions`, `DeleteMarkers`, `IsTruncated`, `NextKeyMarker`, `NextVersionIdMarker`, and all inventory fields exactly for planner validation. AWS documents these marker fields and single-page control ([CLI reference](https://docs.aws.amazon.com/cli/latest/reference/s3api/list-object-versions.html)).
- `list_multipart_uploads`: `list-multipart-uploads --bucket --expected-bucket-owner --prefix snapshots/ --max-uploads 1000`, with both continuation markers when present; preserve truncation and next markers.
- `list_parts`: `list-parts --bucket --expected-bucket-owner --key <validated snapshots key> --upload-id <opaque id> --max-parts 1000`, with `--part-number-marker` when supplied; preserve parts and next-marker fields. The official reference confirms this operation is paginated and supports expected bucket owner ([CLI reference](https://docs.aws.amazon.com/cli/latest/reference/s3api/list-parts.html)).
- `delete_versions`: reject empty/oversized batches and any key outside the fixed prefix; require each entry to contain a nonempty exact `Key` and `VersionId`; write JSON to a mode-0600 file beneath an owned private temporary directory and pass `--delete file://<path>` as one argv element. Set `Quiet` to `false` so the planner can compare every requested item to the response; an omitted per-item confirmation or any `Errors` entry must fail. The CLI's default verbose response includes per-item outcomes, while quiet mode omits successful deletions ([CLI reference](https://docs.aws.amazon.com/cli/latest/reference/s3api/delete-objects.html)).
- `abort_multipart`: pass fixed bucket, owner, validated key and exact upload ID to `abort-multipart-upload`. Do not regard abort's success alone as proof that parts are gone; the planner's subsequent parts inventory must establish that.

Use strict JSON parsing (reject duplicate object keys, invalid UTF-8, non-object roots, unknown/missing fields required by the downstream planner, and oversized/trailing data) and validate the returned response shapes. Do not turn a successful but malformed response into an empty page. For nonzero exit status, parse only bounded stderr as the CLI's structured JSON error. Return `UploadNotFound` only on a single `list-parts` call with the exact `NoSuchUpload` service error code and the expected service-error exit status; every other code, unparsable stderr, or status mismatch propagates a generic adapter failure. AWS documents distinct exit statuses for service, configuration, and general errors; code 255 is explicitly a catch-all and is not a service absence signal ([AWS CLI return codes](https://docs.aws.amazon.com/cli/latest/topic/return-codes.html)). Do not expose raw stderr in user-facing errors or logs.

Bound each child with an explicit wall-clock deadline and strict stdout/stderr byte ceilings. Stream-drain both pipes; on timeout or ceiling breach terminate the owned process group, wait a bounded time, then fail. Because `Popen.communicate()` accumulates arbitrary output before a post-hoc size check, a future implementation should use a bounded streaming loop or equivalent capped sink. Set a private scratch directory for delete request JSON and remove only files created there. Tests must prove cleanup when the child fails, times out, or emits oversized output.

## Local controls

Use an isolated fake executable that records argv and returns fixture JSON/errors; do not point tests at ambient `aws` credentials or a network endpoint. Cover exact argv and all four operations; owner/bucket/prefix mismatch rejected with zero child invocations; explicit manual continuation on each list operation; one page only; malformed, duplicate-key, truncated, oversized, and trailing JSON refusal; `NoSuchUpload` maps only for ListParts and exact structured code/status; AccessDenied, NoSuchKey, NoRegion, timeout, malformed structured errors and generic 255 do not map to absence; delete `Quiet:false`, <=1000 item cap, exact key/version binding, every requested confirmation present, API item errors fail; child cancellation/output cap kills and reaps the owned process group; temp request file is private and cleaned. These prove adapter behavior only, not S3 semantics or IAM.

## Constraints and limits

Do not add a boto3 dependency or inspect the AWS CLI's private botocore bundle. The prior boto3 proposal is rejected because the hosted bootstrap installs AWS CLI v2 (`deploy/hosted/bootstrap.sh`) and does not package boto3. Keep the library and adapter unwired: no `purge.py`, unit/timer, uploader/download integration, credentials setup, or production entry point in this slice. The fixed prefix is consistent with `backup_retention.SNAPSHOTS_PREFIX`; `deletion-journal/` is explicitly excluded and must never be inventoried or deleted.

Before any future wiring, coordinator must freeze the exact executable/config provenance contract and process environment policy (especially preventing ambient endpoint overrides or injected profiles from redirecting requests), resource ceilings, and serialized delete-plan approval boundary. T23.52 still needs an installed hourly service/timer, task54 stack-scoped IAM/alarms, task57 installation, task64 runtime proof, and task66 live disposable-bucket qualification of all versions/delete markers/multipart cleanup and the 31-day maximum. This source-only adapter does not authorize deletion or prove retention.

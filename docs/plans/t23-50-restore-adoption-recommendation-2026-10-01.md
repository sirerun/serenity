# T23.50 restore and writer-adoption implementation recommendation

Reviewed source: `origin/main` at `06e22d019dccd04963f6309c13e0b45f441c7e8a` (PR #337 merged). This is a design receipt only. T23.50 remains `planned`; no provider calls, production edits, or acceptance evidence were produced.

## Smallest safe implementation

Start in the task-owned `internal/hosted/recovery/**` and `internal/cli/hosted_recovery.go` paths with a private, immutable plan artifact and a single-account apply path. Reuse `contracts.RecoveryPlan`, `RecoveryPlanRequest`, `RecoveryApplyRequest`, `RecoveryApplyResult`, `RecoveryPlanner`, `RecoveryApplier`, and `WriterFencer` from `contracts/backup.go`, plus `FenceReceipt.SufficientFor` from `contracts/fence.go`. Do not add an activate-all path or SQL status override.

`plan` should validate one manifest-v2 snapshot in a private scratch destination, bind its manifest/source object ID, exact schema, journal watermark, configured fence generation, provider observation time, and eligible opaque account IDs, then persist canonical plan bytes and their SHA-256 in a private recovery staging directory. `apply` must load those exact bytes, verify the supplied plan hash is unchanged, accept one account ID present in the plan, re-check current provider truth, and persist resumable phase transitions before side effects. The result must pass `RecoveryApplyResult.Consistent(plan, request)` before any account becomes active. Deleted-account and brain journal intents are reconciled before sign-in; a surviving canceled/Free account is not restored to historical paid access. Restore into a fresh temporary destination and publish only after every phase succeeds, so an interrupted apply leaves no partially admitted destination and can be retried.

The CLI needs a patch request to the `internal/cli` and `internal/hosted/service` integrators. The existing `LifecycleDependencies` seam already injects one shared `Journal`, release `BuildSHA`, and a `RecoveryAdmission`; service assembly calls `Admit` before reading the journal, requires both the snapshot-cut and full-history reads to be sealed at the same boundary, verifies pending intents, replays deletions, then constructs/publishes handlers and workers. The admission object must therefore be created from a completed, validated restore/apply record and refuse startup unless it proves this exact restore and the active successor writer. Keep it unavailable until the operator has completed the required fence/adoption actions. The service and backup integrators must pass the same configured journal instance; no empty filesystem journal or synthesized zero watermark may be used in production.

## Required old-writer and successor proof

`FenceReceipt.SufficientFor` checks shape and plan binding; its booleans are not evidence by themselves. The concrete fencer must persist independently checkable references for all three facts in the contract: the old generation’s durable seal after the plan watermark, control-plane evidence that the old writer instance is stopped, and proof that every credential/session it could use is revoked or denied. A copied lock file, elapsed lease, process-local lock, static generation setting, or `ReadThrough(...).Sealed` result cannot prove the other facts. After that fence, the trusted coordinator must perform an explicit durable successor-generation adoption/write authorization and bind the resulting active writer identity and generation to the recovery record injected as `RecoveryAdmission`. A configured generation number or visible empty successor prefix is not adoption.

Keep phases idempotent and fail closed: freeze first; stop and fence the old writer; reconcile journal and account state; reconcile provider truth; rotate/revoke all pre-restore credentials and sessions; then unfreeze one eligible account. A journal/provider outage or changed snapshot/plan leaves the affected account frozen. Persist phase receipts without secret, customer, token, or raw infrastructure identifiers; include only minimized opaque references and verification times in the report.

## Existing provider-free test boundary

`service/lifecycle_deps_internal_test.go` and `service/lifecycle_deps_external_test.go` create real local generation-1 and generation-2 filesystem journals, seal the prior generation, and inject a `testRecoveryAdmission` that asserts it receives the same journal and returns an explicit local-fixture cut. Those tests prove assembly ordering and fail-closed dependency checks only; the fixture adapter is not a production admission proof. `contracts/semantics_test.go` exercises missing, malformed, wrong-generation, and stale `FenceReceipt` fields, while `contracts/contractstest/cross_host_lock_test.go` demonstrates why a copied local writer lock cannot fence another host. Keep provider tests deterministic by injecting fencer/control-plane interfaces and faulting every proof independently; live provider behavior belongs to the separately authorized qualification window.

## Inputs still requiring operator action

Implementation can validate shape, hashes, account scope, phase transitions, and fake-provider failure cases locally. It cannot manufacture or infer the following inputs: which exact retained snapshot the operator authorizes; the operator-approved plan hash and per-account apply decision; the old instance identity and authoritative stop evidence; a complete inventory and revocation/denial receipt for the old writer’s credentials and already-issued sessions; the real durable journal seal and adopted successor identity; or fresh provider truth for current subscriptions and pending checkout state. No real credential source for production journal writes or scoped cloud permissions was established in this review. Preserve the application’s IMDS denial; do not assume the app can use an instance role or grant it a broad host role to make the workflow pass. Missing evidence blocks activation, not a reason to substitute local test seams.

Request CLI registration, `LifecycleDependencies` admission construction, and shared-journal/backup assembly from the integrators rather than editing their files.

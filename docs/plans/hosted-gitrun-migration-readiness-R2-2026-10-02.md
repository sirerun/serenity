## Implementable source contract

Use the existing `internal/gitrun` methods and trust levels; make no library/API change unless a regression proves the behavior cannot be expressed through the current API.

- For reads that decide what the committed repository means, use `gitrun.CanonicalReadOnly(root)`: in `pool.open`, the `rev-parse --verify HEAD` and `ls-tree ... config.FileName` checks; in `provision/canonical.go`, `rev-parse --verify HEAD` and `show HEAD:.gitignore`. This pins replacement-object and lazy-fetch behavior and prevents inherited `GIT_*` values from redirecting the read. Do not use `Brain` for those proofs.
- Use `gitrun.Brain(root)` for writes to the locally owned canonical repository: `config --local`, `add`, and the config/baseline `commit`. The runner prepends its hardening options and rejects caller options such as `-C` and `-c`; construct arguments relative to its bound root, without either option. Use `CombinedOutput`, `Output`, or `Command` with the same caller `ctx` and preserve `%w` plus captured stderr/stdout in the current error context.
- For commits whose identity is currently supplied with `-c user.name/email`, call `Brain(root).Command(ctx, "commit", ...without -C/-c...)`, then append exactly these four fixed, code-owned entries to that returned command's already-scrubbed `Env` before `CombinedOutput`: `GIT_AUTHOR_NAME=Serenity Hosted`, `GIT_AUTHOR_EMAIL=hosted@serenity.sire.run`, `GIT_COMMITTER_NAME=Serenity Hosted`, and `GIT_COMMITTER_EMAIL=hosted@serenity.sire.run`. Append no caller-derived values, `GIT_CONFIG_*`, `GIT_DIR`, or other environment variables. Do not add `-c` or `--config-env`; the runner intentionally rejects them. The persistent `config --local` identity in canonical provisioning remains required for later writer commits.
- Keep the subcommands, path scopes, messages, and commit inclusion semantics otherwise stable. Pool must still inspect whether the runtime config is tracked at HEAD; if it is tracked, do not create another baseline commit; if not, stage only the required config/baseline paths and preserve `commit --only` so unrelated index entries are not included. Preserve configured embedder model pin validation and retry convergence when a canonical `.git` directory already exists.

One existing runner boundary needs care: `CanonicalReadOnly` shares Foreign's read-only subcommand allowlist. It admits `rev-parse`, `ls-tree`, and `show`, but not `symbolic-ref`. `initializeCanonical` currently uses `symbolic-ref --quiet HEAD` only to admit an unborn symbolic HEAD for a retry. Do not silently route that read through `Brain` or widen the allowlist. First preserve the invariant without a runner change by validating the owned `.git/HEAD` file as a regular file with the exact expected symbolic target (`ref: refs/heads/main`) after `Lstat` has established that `.git` is a real directory; otherwise return the existing failure. If regression evidence shows that this filesystem check cannot preserve the current retry/corruption distinction, document that evidence and add only the narrowly required read-only command to the runner allowlist with a runner-level test. No other API change is justified by this task.

## Pool fail-closed and side-effect ordering

In `internal/hosted/pool/pool.go`, validate `root` as today, then `Lstat(root/.git)` before `writer.AcquireBrain`, any nested `MkdirAll`, `config.Save`, or Git invocation. Missing `.git` returns a corruption/not-a-repository error. A symlink or non-directory `.git` returns an unsafe-Git error. The open path must never call `git init`; creation is owned by `Provisioner` during the allocating-to-ready transition. Keep the existing configured model pin check and config tracking/commit retry behavior for an already present safe canonical repository. A failed preflight must leave the brain directory byte-for-byte and entry-for-entry unchanged, and must not change the persisted ready row.

This preflight order matters because current `open` creates internal brain directories and may save `serenity.yml` before checking Git. `writer.AcquireBrain` may also create lock metadata, so place the `.git` check ahead of it to satisfy the no-write-on-missing-repository contract. Do not touch runtime fences or sealed deletion-journal behavior.

## Genuine regression designs (not executed)

1. **Missing Git, real pre-fix RED.** Create a ready brain fixture with no `.git` and no runtime config. Snapshot its complete tree and row. Call the pool open path. Require missing-Git failure before `AcquireBrain`/mkdir/config save, unchanged tree and row, and no Git history. The current source creates nested directories and config before its absent-`.git` branch initializes Git, so this assertion exposes the current unsafe behavior. Repeat with `.git` as a symlink and as a regular file; both must fail with no side effects and no recreation.
2. **Inherited Git redirection, real pre-fix RED.** For an existing canonical brain, set process `GIT_DIR` to a separate invalid Git directory. A pool open must still use the brain's own HEAD/config and must not touch the external directory. Current raw `exec.CommandContext` inherits `GIT_DIR`, so the Git reads are redirected and opening fails; `gitrun` removes it. Separately set `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0=core.fsmonitor`/`GIT_CONFIG_VALUE_0=<owned marker executable>` and run the pool commit path, asserting the marker stays absent when that Git operation consults fsmonitor. The runner's existing `TestHostileFsmonitorNeverSpawns` is the direct fsmonitor security proof; do not claim the pool callsite test is a RED unless the chosen operation is observed to invoke it. Keep all fixtures test-owned and assert exact before/after HEAD and external-tree hashes.
3. **Cancellation is a preservation control, not a RED claim by itself.** A pre-canceled context with a missing runtime config must return an error matching `context.Canceled` before any config/directory write. Current pool opens the writer owner, creates internal paths, and may save config before it reaches Git, so the no-side-effects assertion is a genuine pre-fix RED. Also use a blocking test-local `git` executable during canonical initialization to prove cancellation stops the process, leaves the row `allocating`, and preserves only the allowed retry state. Do not claim that a plain `CommandContext` cancellation test alone distinguishes raw exec from gitrun; both APIs accept a context.
4. **Config and identity preservation.** Keep/extend `TestProvisionedBrainCommitsConfigOnFirstOpenAndRetry`: first open commits the model-pinned config once, retries do not create duplicate baseline commits, and a pre-staged unrelated file is absent from the resulting commit. Verify commit author and committer are the four fixed service identity values when run under hostile inherited `GIT_*` variables.
5. **Canonical safety/retry.** Retain provision tests for committed `.gitignore` exact bytes, persistent local identity, commit-before-ready durability, failed commit leaving `allocating`, interruption retry, and symlink/non-directory `.git` refusal. Add a focused detached/corrupt/unborn HEAD regression because the inspected provision tests do not establish that distinction. The retry path must not invoke an unsupported read-only runner command unless a narrowly reviewed allowlist change is proven necessary.
6. **Lifecycle migration.** Test exact bundle args, caller cancellation, command output/error wrapping, temporary bundle cleanup, and that only the authenticated account/brain's pool runtime root is used. These validate this migration slice; history-free export, dashboard status/logging, and T23.48 completion are explicitly out of scope here.

# T23.52 retention library receipt — 2026-10-01

Implemented on main #332 baseline `230234c969058807236af76d91da0967357a37cd`, following the planner design in `5396048f478c419d2fe8080cd0921819b6dd3c5c`. This is an unused local library candidate only. It does not wire a purge worker, timer, CLI, IAM policy, lifecycle rule, upload path, or production backup service. No AWS calls or external object operations were made.

`deploy/hosted/backup_retention.py` defines a storage adapter seam plus complete inventory, canonical plan serialization/loading, and an explicit apply operation. The fixed namespace is `snapshots/`; every returned key is checked as exactly `snapshots/YYYYMMDDTHHMMSSZ/...`. One timezone-aware UTC clock establishes the 29-day snapshot cutoff and 1-day incomplete-multipart cutoff. The planner traverses every versions/delete-markers page and every multipart page with both continuation markers, rejects malformed or repeated tokens and foreign/malformed keys, and applies bounded page, item, part, and serialized-plan limits by failing rather than truncating.

The frozen plan binds bucket, expected owner, prefix, generation time, both cutoffs, every exact version/delete-marker identity and multipart upload identity, timestamps, and a SHA-256 digest. Every storage call receives the exact approved bucket and expected owner. `apply` requires the reviewed digest, matching bucket/owner, a plan generation time no later than the apply clock, and a fresh complete inventory identical to the approved inventory. It uses the plan's frozen cutoffs for candidate checks and its postcondition, so an older approved plan never expands to include items that became age-eligible later. The returned result identifies both verified cutoffs so callers can distinguish an older reviewed scope from current policy. A scheduled caller must generate and record a fresh plan at each run if it needs to enforce the current cutoff. `apply` rechecks eligibility, deletes exact version IDs in batches of at most 1,000, refuses any deletion error or incomplete/unexpected response, aborts only uploads eligible under the frozen one-day cutoff, checks that their parts are gone, then takes another full inventory and errors if eligible versions, markers, or uploads remain under those same reviewed cutoffs. The returned report includes deletion counts and oldest surviving snapshot/LastModified timestamps and ages.

Inventory validation requires boolean `IsLatest` values, unique version identities and multipart upload IDs, and rejects snapshot prefixes, `LastModified`, and multipart initiation times later than the captured UTC clock. Aware SDK datetime values are normalized to UTC; naive datetimes and malformed strings fail closed. For multipart part verification, the adapter may report only an authoritative S3 `NoSuchUpload` as `UploadNotFound`; permission, transport, and other API errors propagate and cannot be converted to an empty-parts success.

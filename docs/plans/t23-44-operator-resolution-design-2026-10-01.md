# T23.44 pending-review operator resolution design

Review pins: merged main337 `06e22d019dccd04963f6309c13e0b45f441c7e8a`; conservative accounting candidate `c0c530fa86b205e5e40b5324559472e612147b7d`. This is a design receipt, not implementation or acceptance evidence. The candidate wires startup and periodic reconciliation for expired `reserved` rows, but leaves `pending_review` for an operator as required by the frozen state machine.

## Current contracts and proof path

`internal/hosted/contracts/operations.go` defines `OperationLedger.ResolvePendingReview(ctx, operationID, outcome, evidence)` as the only exit from `pending_review`. `ValidateTransition` permits an `ActorOperator` to resolve only to `committed` or `released`, with `EvidenceOperatorReview` and a non-empty reference. The concrete `operation.Ledger.ResolvePendingReview` assigns that actor internally and performs the state transition transactionally. `ReconcilePending` currently selects only expired `reserved` rows; it does not select or resolve pending-review rows. The service ticker therefore does not create an automatic exit.

The positive canonical proof path already exists. `gateway.OperationReconciler.Fence` verifies the brain/account is active and ready, validates the brain tree, then holds the runtime queue's exclusive commit fence. Its `Check` verifies the record still maps to that active brain and calls the checker bound to the exact fenced runtime. `pool.Reconciler.Check` fails closed unless that same reconciler still holds the runtime fence. `pool.Runtime.Check` can return `CanonicalLanded` only for canonical evidence matching the operation record; this is the only machine proof suitable for a committed operator resolution. The service must keep the release closure live across `Check` and the ledger transition, then release it on every path.

The minimal committed flow is: authenticate an operator on the private admin transport; load the operation by internal ID and require `pending_review`; acquire the same `OperationReconciler`'s fence for its brain; call its checker; if and only if the result is `CanonicalLanded`, call `ResolvePendingReview(..., OperationCommitted, Evidence{Kind: EvidenceOperatorReview, Ref: reviewRef})` before releasing the fence. Pass `reviewRef` unchanged so the ledger binds the final row to the reviewed case; that immutable case must identify the operator and include the checker result/reference. The transition changes phase/evidence/finalized time and leaves the original quota deltas intact. Return the operation's generic final state, not customer payload or the client key. Re-read/CAS in the ledger transition remains authoritative if another resolver won the race. A fence, lookup, context, or ledger failure leaves the row unresolved and capacity-holding.

`CanonicalUnknown`, checker errors, `CanonicalAbsent`, malformed evidence, and missing/inactive brains must never be converted into `released` or reported as landed by this path. The candidate checker intentionally does not provide a safe post-purge absence proof. Automatic sweeps continue to leave unknown rows in `pending_review`. Do not synthesize `EvidenceAbsent` or treat lease expiry as proof.

## Authorization and contract gap

The registry requirement in `docs/tasks/hosted-completion/T23.44.md` asks for a resolver on the admin socket. In this candidate, `Service.AdminHandler` has partner and backup routes, but repository search finds no production call site mounting it; it is not attached to the public `Service.Handler`. The backup client names a `.hosted-admin.sock`, but that client-side dial does not prove a protected server listener exists. There is no operator principal or authorization interface in the operation ledger or service. Therefore a new route must not be added to the public/dashboard/MCP handler or treated as authorized merely because it is named “admin.” The integration must first provide an owner-only local Unix-socket listener with an explicit OS-identity check (or a separately reviewed operator authenticator), and must not accept the actor identity from the request body. Until then the safe behavior is no reachable resolver.

The contract permits a human operator to choose `released` with `EvidenceOperatorReview`; it does not define what external evidence justifies that choice or whether a checker `Unknown` may be overridden. The current ledger persists only one evidence reference, so it cannot independently persist both the operator's case reference and the canonical checker reference. The smallest safe implementation is therefore a positive-proof-only commit endpoint; do not offer `released` until an explicit policy defines the required human evidence and its durable binding. Do not encode a canonical ref as an operator review ref or claim the former proves the latter. Unknown stays in `pending_review`; no background path may make that decision.

## Smallest implementation slice and controls

If the existing private admin transport and immutable review-record source are supplied, keep production ownership narrow:

- Add a read-only operation lookup in `internal/hosted/operation/ledger.go` (without changing the frozen `OperationLedger` interface) that returns the record needed for internal orchestration and never exposes its client key/fingerprint over HTTP.
- Add service orchestration in `internal/hosted/service/operation_reconcile.go` and a strict `POST` route in `internal/hosted/service/service.go`. Validate the operation ID, outcome, and bounded review reference; reject unknown JSON fields and trailing data. Require the trusted operator context from the admin listener, not a caller-supplied role.
- Reuse `gateway.OperationReconciler`'s exact `Fence -> Check -> ResolvePendingReview` path for a committed decision. Keep the fence through the DB transition and release in a defer. Do not expose a release action until its manual-evidence policy is approved; never call it a canonical-absence result.
- Test positive landed settlement under one fence; an injected blocking writer proving the fence waits; unknown/error/inactive/cold-runtime paths staying pending; committed-vs-released conflict races; unauthenticated and public HTTP access denied; invalid/oversized review references rejected; and capacity unchanged on every refusal. Exercise existing stores and HTTP handlers with local fixtures only.

No implementation or Go tests were run for this design task. The service CLI's current fail-closed startup boundary and the absent admin-listener mount remain separate integration prerequisites; this receipt does not claim a production operator path, T23.44 acceptance, absence evidence, or deployment readiness.

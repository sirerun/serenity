# Verifying release artifacts

Hosted deployment verifies the downloaded archive with Cosign before
extracting or installing it. The signature bundle must identify the exact
Serenity release workflow run for the matching tag and use GitHub Actions as
the OIDC issuer. The deployment then checks the caller-provided SHA-256 before
extracting the binary.

Release archives and `checksums.txt` are signed with Cosign keyless bundles.
Each archive also has a CycloneDX SBOM generated by Syft, and GitHub publishes
a provenance attestation for the release archives. The deployment verifier
accepts only the archive signature, so a matching checksum from the same
release cannot substitute for its publisher identity.

To verify an archive locally, download its `.sigstore.json` bundle and run:

```sh
cosign verify-blob \
  --bundle serenity_VERSION_linux_arm64.tar.gz.sigstore.json \
  --certificate-identity 'https://github.com/sirerun/serenity/.github/workflows/release.yml@refs/tags/vVERSION' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  serenity_VERSION_linux_arm64.tar.gz
```

Replace `VERSION` with the numeric release version, including prerelease text
when present. Verify the archive signature before checking its checksum or
extracting files.

Gitleaks also scans commit history. `.gitleaksignore` lists fingerprints for
deterministic hosted-test fixtures that predate the inline `gitleaks:allow`
comments. Those exceptions are scoped to the exact historical commits and
lines; the current working tree scans cleanly without ignore entries.
